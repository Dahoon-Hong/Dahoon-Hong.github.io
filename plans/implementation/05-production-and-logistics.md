# 05. 생산과 물류

## 목표

시스템 문서의 자원 흐름을 실제 게임 규칙으로 연결한다.

`자원 → 재활용기 → 물질 → 무기고 → 탄약`

`물질 → 물질 합성기 → 나노 물질`

## 선행 조건

- [04 자원 획득과 저장](04-resource-collection.md) 완료
- 변환 비율, 생산 시간, 각 자원의 저장 한도를 아래 MVP 규칙으로 결정

## MVP 규칙

### 자원 저장

- 자원 종류는 `resource`, `matter`, `ammo`, `nano` 네 가지로 고정한다.
- 각 자원의 저장 한도는 100이다.
- 초기값은 `resource: 50`, `matter: 0`, `ammo: 0`, `nano: 0`이다.
- 게임 시작과 재시작 시 차량 주변에 자원 픽업 10개가 생성되며, 각 픽업은 자원 10을 가진다.
- 수집기 1개가 기본 설치되어 초기 픽업을 회수한다.
- `ResourceStorage`가 네 자원의 현재량·저장 한도·획득·소비·초기화를 단일 책임으로 관리한다.
- 저장 공간이 부족하면 획득량을 저장 가능한 만큼만 반영하고, 생산 입력은 소비하지 않는다.

### 생산과 변환

- 자원 생산기: `resource 10`, 생산 간격 1초
- 재활용기: `resource 10 → matter 5`, 생산 간격 1초
- 무기고: `matter 5 → ammo 1`, 생산 간격 1.5초
- 물질 합성기: `matter 10 → nano 1`, 생산 간격 2.5초
- 생산 모듈은 출력 버퍼를 가지며, 출력 버퍼가 가득 차면 입력을 소비하지 않는다.
- 입력이 부족하거나 모듈이 비활성화된 경우 생산하지 않는다.
- 나노 물질은 현재 소비처가 없으므로 저장까지만 구현한다.

### 물류

- 생산 모듈의 출력은 모듈별 버퍼에 쌓는다.
- 코어/저장고에서 격자 기준 1칸 이내(상하좌우·대각선 8방향)의 출력은 `Rail` 없이 저장고로 자동 수집한다.
- 자연 수집 범위를 벗어난 출력은 `Rail`이 장거리 운송한다.
- 여러 생산 모듈의 출력은 고정된 순서로 처리하며, `ammo` 출력은 공격 모듈이 사용하는 자원이므로 다른 출력보다 먼저 운송한다.
- 연결 그래프, 분기, 자동 최적화는 구현하지 않는다.

### 탄약과 일시정지

- 직사·곡사 무기는 발사 전에 `ammo` 1을 소비한다.
- 탄약이 부족하면 발사하지 않고 탄약도 소비하지 않는다.
- 일시정지 중에는 생산·운송·탄약 소비가 진행되지 않는다.
- 01 기준을 유지해 일시정지 중 모듈 설치·업그레이드는 허용한다.

## 작업 대상

- `src/entities/Module.ts`
- `src/core/Game.ts`
- `src/ui/HUDManager.ts`
- `src/core/ResourceStorage.ts`
- 필요 시 생산 전용 파일

## 작업 순서

1. `ResourceStorage`를 네 자원 타입과 자원별 저장 한도를 관리하도록 확장한다.
2. 재활용기와 무기고를 최소 생산 모듈로 구현한다.
3. 물질 합성기는 나노 물질을 생산하되, 나노 물질의 실제 소비처가 없으면 저장까지만 구현한다.
4. HUD에 네 자원의 현재량과 저장 한도를 표시한다.
5. 무기 발사 전에 탄약을 확인하고, 부족하면 발사하지 않는다.
6. 생산 모듈의 입력 부족·출력 저장 공간 부족·비활성 상태를 처리한다.
7. 코어/저장고에 인접한 생산 모듈의 출력 자동 수집과 `Rail`의 장거리 운송을 구현한다.
8. 레일의 연결 그래프, 분기, 자동 최적화는 실제 필요가 생길 때까지 미룬다.

## 완료 기준

- 각 변환이 정의된 입력을 소비하고 정의된 출력만 생성한다.
- 탄약이 없으면 무기가 공격하지 않는다.
- 저장 공간이 없으면 입력을 소비하지 않거나 초과분을 잃지 않는 규칙이 적용된다.
- 일시정지 중 생산·운송·탄약 소비가 진행되지 않는다.
- HUD에서 네 자원의 현재량과 저장 한도를 확인할 수 있다.
- Rail 없이도 코어/저장고 인접 8방향의 생산 출력이 수집된다.
- `ammo` 출력이 다른 생산 출력보다 먼저 운송되고 공격 모듈의 발사에 사용된다.

## 검증

- 입력 부족, 출력 저장 공간 부족, 모듈 파괴 상태를 각각 확인한다.
- 탄약이 0일 때 직사·곡사 무기 모두 멈추는지 확인한다.
- 생산된 탄약이 발사 한 번마다 정해진 수량만큼 줄어드는지 확인한다.
- Rail 없이 상하좌우·대각선 1칸 생산 모듈의 출력이 수집되는지 확인한다.
- Rail로 자연 수집 범위 밖의 출력이 이동하는지 확인한다.
- 여러 출력이 동시에 대기할 때 `ammo`가 먼저 이동하는지 확인한다.
- 일시정지 중 설치·업그레이드는 가능하지만 생산·운송·탄약 소비는 멈추는지 확인한다.
- `npm run build`

## 구현 결과

- `ResourceStorage`에 `resource`, `matter`, `ammo`, `nano` 저장소와 자원별 용량·획득·소비를 구현했다.
- Recycler, Arsenal, Matter Composer 생산 모듈과 출력 버퍼를 구현했다.
- 코어/저장고 인접 8방향의 출력 자동 수집과 Rail의 장거리 운송, 무기 발사 전 탄약 소비, HUD 자원 표시를 연결했다.
- 탄약 출력은 운송 우선순위를 가지며 공격 모듈이 사용하는 전역 `ammo` 저장고로 먼저 이동한다.
- 일시정지 중 생산·운송·탄약 소비는 중단하고 모듈 설치·업그레이드는 허용한다.
- `tsc`와 Vite 대체 출력 경로 빌드를 통과했다. 기본 `dist` 출력 경로는 기존 디렉터리 권한 문제로 별도 확인이 필요하다.
