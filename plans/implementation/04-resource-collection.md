# 04. 자원 획득과 저장

## 목표

적 처치와 잔해에서 얻은 자원을 안전하게 저장하고, 모듈 설치·업그레이드에 사용할 수 있는 자원 시스템을 만든다.

## 선행 조건

- [03 전투 MVP](03-combat-mvp.md) 완료

## 작업 대상

- `src/core/Game.ts`
- `src/entities/Enemy.ts`
- `src/entities/Module.ts`
- `src/ui/HUDManager.ts`
- 필요 시 새 자원 엔티티 파일

## 작업 순서

1. 단일 `resources` 숫자 사용을 자원 지갑 또는 저장고의 명확한 책임으로 정리한다.
2. 적 처치 보상을 중앙 경로에서 한 번만 지급한다.
3. 수집기 모듈의 최소 규칙을 정한다. 초기 구현은 적 처치 지점 또는 잔해에 가까이 가면 회수하는 방식으로 한다.
4. 저장 한도를 추가하고 한도 초과 시 획득 결과를 명확히 처리한다.
5. HUD에 현재 자원과 저장 한도를 표시한다.
6. 기존 상점·업그레이드가 새 저장고 API를 사용하도록 연결한다.
7. 자원 종류가 늘어나기 전까지는 `resource` 단일 종류로 유지한다.

## 완료 기준

- 적 처치 또는 수집으로 자원이 증가한다.
- 자원은 저장 한도를 초과하지 않는다.
- 설치·업그레이드는 저장된 자원만 소비한다.
- 자원 획득과 소비가 일시정지 중에는 발생하지 않는다.
- 게임 시작과 재시작 시 차량 주변에 자원 픽업 10개가 생성되며, 각 픽업은 자원 10을 가진다.
- 게임 시작 시 수집기 1개가 기본 설치되어 초기 픽업을 회수할 수 있다.
- HUD가 현재량과 최대량을 정확히 표시한다.

## 검증

- 적 처치 보상이 중복 지급되지 않는지 확인한다.
- 저장 한도에 도달한 뒤 추가 획득을 확인한다.
- 자원 부족 상태에서 설치·업그레이드가 실패하고 자원이 변하지 않는지 확인한다.
- 재시작 시 현재 단계에서 정의한 초기 자원으로 돌아가는지 확인한다.
- `npm run build`

## 다음 단계 조건

재설계 전환 메모: 재설계 이후 수집기는 설치 모듈이 아니라 탱크 생성 시 활성화되는 내장 기본 시스템이다. 이 문서의 기본 수집기 설치는 당시 구현 기록으로 보존하며, 새 시작 흐름에서는 JSON의 `builtinModuleIds`로 활성화와 기본 수치를 검증한다.

자원의 획득·저장·소비가 단일 책임 경로로 동작해야 한다. 이 단계에서는 물질·탄약·나노 물질을 아직 추가하지 않는다.
