# 25.3 Upgrade Web Armory

## 목표

기존 Upgrade Web 시스템 목록에 Armory를 추가하고, Armory 연구 → 전투 모듈 구매 → 설치 대기 상태를 연결한다.

## 선행 조건

- 기존 `UpgradeManager`, `HUDManager` subject/upgrade web 흐름
- [25.1 월드 확장과 카메라](25-world-expansion-camera.md) 또는 screen/world 입력 경계가 정해진 상태
- [Plan 25 설계 명세](../../docs/superpowers/specs/2026-09-06-plan-25-gameplay-expansion-design.md)

## 구현 범위

### 데이터와 로더

- starter tank에 builtin `armory` definition을 추가한다.
- `builtinModuleIds`에 `armory`를 추가한다.
- `armory.json`의 upgrade tree node와 combat module unlock ID를 연결한다.
- combat module definition에 `researchCost`, `purchaseCost`, `fireArcDegrees`, `defaultOrientation`을 추가한다.
- loader가 cost, angle, orientation, unlock module reference를 검증한다.
- 기존 `installCost` 데이터는 호환하고 구매 비용의 fallback으로 사용할 수 있게 한다.

### Armory 상태

- `builtin:armory`를 UpgradeManager에 등록한다.
- research node 선택은 기존 upgrade cost 차감과 sibling branch 규칙을 재사용한다.
- 연구된 combat module의 구매 수량을 런 단위 map으로 관리한다.
- purchase 성공 시 matter를 차감하고 수량을 1 증가시킨다.
- restart/reset 시 연구와 구매 수량을 초기 상태로 되돌린다.
- 시작 direct weapon은 연구·구매·설치 완료 상태로 초기화한다.

### Upgrade Web UI

- 기존 SYSTEMS 목록에 Armory subject를 표시한다.
- Armory 선택 시 기존 upgrade web 구조를 유지하면서 연구 node를 렌더링한다.
- 연구된 모듈에는 purchase control과 보유 수량을 표시한다.
- 구매한 모듈 선택 시 `INSTALL` action을 제공한다.
- 기존 빈 grid cell 기반 직접 설치 목록은 Armory purchase/install 흐름과 중복되지 않도록 정리한다.
- 연구·구매는 PAUSED 중에만 성공해야 한다.

## 완료 기준

- SYSTEMS에 Armory가 표시되고 기존 Upgrade Web과 동일하게 선택된다.
- 연구 전 module은 잠금, 연구 후 purchase 가능, purchase 후 보유 수량이 표시된다.
- matter 부족 시 연구/구매가 실패하고 자원·수량이 변하지 않는다.
- restart 시 Armory 상태가 초기화된다.
- 시작 direct weapon의 기존 플레이 가능성이 유지된다.
- PAUSED가 아니면 연구·구매·설치 action이 거부된다.
- `npm run build` 성공.

## 수동 QA

1. Armory를 선택하고 연구 node의 locked/available/selected 상태를 확인한다.
2. matter 충분/부족 상태에서 research와 purchase를 각각 실행한다.
3. 구매 수량 증가와 matter 차감을 확인한다.
4. 구매한 module의 INSTALL action이 25.4의 ghost placement로 연결되는지 확인한다.
5. restart 후 연구와 구매 수량이 초기화되고 direct weapon만 시작 설치 상태인지 확인한다.
