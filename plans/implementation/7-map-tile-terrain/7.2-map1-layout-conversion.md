# 7.2 — 첨부 레이아웃의 tile 변환

## 목표

임시 clipboard 경로에 의존하지 않고, 승인된 첨부 이미지를 저장소의 안정적인 원본으로 등록한 뒤 18px tile 후보와 marker 좌표를 재현 가능하게 추출한다.

## 구현 범위

- 승인된 원본을 `scripts/map-source/aurelia-landing-zone-layout.png`로 등록한다.
- 기존 PowerShell `System.Drawing` 사용 패턴을 재사용해 `scripts/convert-map1-layout.ps1`를 추가한다.
- 입력 이미지의 투명/검정/빨강/파랑을 분류한다.
  - opaque black: blocked candidate
  - transparent: open candidate
  - red: enemy spawn candidate
  - blue: tank start candidate
- source image를 비율 유지 `contain + center`로 2880×2160에 매핑한다.
- tile center를 기준으로 160×120 rows를 생성한다.
- marker가 포함된 tile은 marker를 지우고 open terrain으로 기록한다.
- report에는 source size, scale, offset, blocked cell 수, spawn/start 후보 cell을 출력한다.
- 사람이 결과를 검토할 수 있도록 원본 위에 18px grid와 추출 marker를 합성한 preview를 만든다.

변환 script는 런타임에서 호출하지 않는다. 생성된 결과를 사람이 검토한 뒤 `maps.json`의 canonical `terrain.rows`와 위치 데이터로 반영한다.

## 검증

- [ ] script를 같은 입력으로 두 번 실행했을 때 rows와 marker report가 동일하다.
- [ ] rows는 120개이고 각 row는 160 symbol이다.
- [ ] red marker는 정확히 4개, blue marker는 정확히 1개다.
- [ ] marker 후보 cell은 모두 open이다.
- [ ] preview에서 검정 영역과 `#` 영역이 tile 경계 기준으로 일치한다.
- [ ] source 이미지의 anti-aliasing 픽셀이 주변 open/blocked 결정을 임의로 흔들지 않는다.
- [ ] 생성 결과와 원본 source의 매핑 offset/scale을 provenance 기록에 남긴다.

## 실패 처리

- red/blue marker가 누락되거나 예상 개수가 다르면 성공 결과를 만들지 않고 오류로 종료한다.
- 한 tile에 서로 다른 marker가 겹치면 오류로 종료한다.
- 월드 밖으로 매핑되는 blocked tile 또는 marker가 있으면 오류로 종료한다.
- 최종 collision 데이터는 이미지가 로드되지 않아도 유지되어야 하므로 PNG를 직접 runtime source로 사용하지 않는다.

## 완료 조건

사람이 preview를 확인한 뒤 7.5에서 사용할 rows·marker 목록을 확정할 수 있는 deterministic report가 생성된다.
