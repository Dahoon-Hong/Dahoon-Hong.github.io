# 7.11 — 1번 맵 탱크 통과 여유 조정

## 목표

현재 1번 맵에서 시각 차체의 크기와 지형 충돌 footprint가 거의 같아 18px 통로를 과도하게 막는다. 시각 차체와 전투 격자는 유지하고, `aurelia/landing-zone`에서만 지형 충돌 판정 폭을 약 3개 tile(54px) 수준으로 줄여 좁은 길을 통과할 수 있게 한다. 기존에 폭이 급격히 좁아지는 연결 구간은 canonical tile row에서 한 칸씩만 확장한다.

## 확정 결정

- 적용 맵은 `aurelia/landing-zone` 하나다.
- 3×3 starter tank의 map1 terrain hitbox는 약 `48.6×48.6px`(18px tile 2.7칸)으로 판정해 3칸 통로에 중심 오차 여유를 둔다.
- 차체 PNG, combat grid, module 배치와 실제 draw 크기는 변경하지 않는다. 따라서 시각 차체 가장자리가 지형 경계에 조금 겹칠 수 있다.
- 다른 맵은 기존 `120×120px` 수준의 terrain footprint와 동작을 유지한다.
- 지형 확장은 `maps.json`의 `terrain.rows`를 canonical source로 수정하고, 같은 rows에서 최종 PNG를 재생성한다.
- start/spawn cell과 큰 외곽 지형은 이동하지 않는다. 좁은 연결부만 18px tile 한 칸 범위로 확장한다.

## 후속 backlog: 열린 방향에서도 발생하는 벽 끼임

### B1. 현상

실제 주행 중 탱크가 벽 근처에서 멈춘 뒤, 화면상 위쪽이나 한쪽 진행 방향이 막혀 있지 않아 보여도 움직이지 않는 경우가 남아 있다. 현재 보고된 화면은 다음 정보를 포함하는 대표 재현 사례로 보관한다.

- 1번 맵의 18px tile terrain
- 탱크가 벽 또는 좁은 연결부의 접점에 걸린 상태
- 위쪽에 열린 공간이 보이지만 입력을 계속해도 이동하지 않음
- 시각 차체와 실제 terrain footprint의 경계 차이를 화면만으로 판단하기 어려움

정확한 원인은 아직 확정하지 않는다. 회전한 footprint의 모서리 접촉, 접촉 여유값, 축별 이동 결과의 전체 취소, 이전 frame의 경계 오차가 후보이며 재현 로그로 구분한다.

### B1. 목표 방향

충돌을 더 관대하게 해 열린 공간에서 빠져나올 수 있게 한다. 단, 실제 blocked tile을 관통하거나 벽 반대편으로 순간 이동하는 완화는 허용하지 않는다.

- map1 탱크의 유효 terrain footprint 또는 접촉 epsilon을 설정값으로 조정할 수 있게 한다.
- 실제 겹침이 아닌 경계 접촉·부동소수점 오차는 blocked로 과잉 판정하지 않는다.
- 한 축 또는 접선 방향이 열려 있으면 충돌한 전체 이동을 취소하지 않고 열린 방향 이동을 시도한다.
- 안쪽 코너에서 두 축이 모두 막힌 경우에는 안정적으로 멈추되, 입력을 반대로 했을 때 빠져나올 수 있어야 한다.
- 렌더링 차체와 combat grid 크기는 유지하고, map1 terrain 판정만 완화한다.

### B1. 세부 진행 및 검증

1. 재현 시점의 월드 좌표, tile 좌표, 탱크 회전각, 입력 벡터, 이전/후보 위치와 충돌한 cell 목록을 debug log로 수집한다.
2. 후보 footprint와 실제 blocked tile을 debug overlay로 함께 표시해 “위쪽이 열려 보임”과 실제 접촉 cell의 차이를 확인한다.
3. 접촉 epsilon, map1 footprint scale, 축별/접선 이동 해소 중 어느 값이 정지를 유발하는지 한 번에 하나씩 조정한다.
4. 최소 완화값을 선택한다. 열린 방향에서 탈출 가능해야 하지만 blocked tile 안으로 중심이 진입하거나 차체가 벽을 관통해서는 안 된다.
5. 정면 접근, 대각선 접근, 안쪽·바깥쪽 코너, 좁은 길 입구, 후진, 30/60/120fps frame delta에서 회귀 테스트를 추가한다.
6. 실제 1번 맵에서 동일 재현 위치와 반대 방향 탈출을 integration-tester로 확인한다.

### B1. 완료 기준

- 보고된 위치에서 위쪽 또는 다른 열린 방향 입력으로 탱크가 다시 이동한다.
- 열린 방향이 있어도 전체 이동이 0으로 고정되는 재현 케이스가 없다.
- blocked tile 관통, 반대편 순간 이동, 코너 무한 진동이 없다.
- 3칸 통로와 기존 7.11 회귀가 유지된다.
- map2~map4와 test map의 충돌 판정은 변경되지 않는다.
- `npm test`, `npm run build`, `npm run dev` 실제 조작 및 integration-tester가 PASS다.

이 backlog는 현재 7.11 완료 커밋의 범위를 되돌리지 않고, 원인 로그와 최소 완화값을 확보한 별도 후속 수정으로 처리한다.

### B1 구현 상태 기록 — 2026-09-12

- map1에 `tankCollisionShape: "circle"`을 추가하고, 기존 `TerrainGrid` 원형 sweep API를 `Vehicle` 이동·위치 검증에 연결했다.
- map2~map4와 test map은 `rect` 기본값을 유지한다. F3 overlay도 실제 map1 원형 footprint를 표시한다.
- `npm run qa:release`는 47 tests, art/audio QA, build까지 통과했다.
- 로컬 Computer Use에서는 map1 진입, F3 원형 footprint, canvas focus 후 반복 WASD 이동과 콘솔 오류 없음을 확인했다.
- 공식 `integration-tester`는 F3 표시까지 확인했으나 키 입력 후 실제 이동을 관찰하지 못해 `BLOCKED`로 보고했다. 공식 PASS 전에는 원격 PR 갱신을 보류한다.
