# 7.3 — variable cell size와 map loader 검증

## 목표

현재 `MapDefinitionLoader`가 모든 맵의 cell size를 36으로 강제하는 전제를 제거하고, 1번 맵만 18px로 안전하게 로드한다. 기존 맵의 36px 동작은 그대로 유지한다.

## 구현 범위

- `world.cellSize`를 양의 정수로 검증하고, world width/height를 `columns × cellSize`, `rows × cellSize`로 계산한다.
- 필요한 경우 현재 프로젝트가 지원하는 cell size를 `18`과 `36`으로 제한해 임의의 미지원 값은 명확히 거부한다.
- rows 기반 map1과 regions 기반 기존 맵을 계속 분리해서 읽는다.
- map1 artwork size와 grid 계산 결과가 일치하는지 검증한다.
- map1 시작점과 네 스폰점이 내부이며 open인지 검증한다.
- `qa:art`의 “artwork map은 rows를 사용할 수 없음” 규칙을 map1의 새 계약에 맞게 수정한다.
- raw JSON을 직접 참조하는 호출부가 cell size를 36으로 가정하지 않는지 확인한다.

## 테스트

`MapDefinitionLoader.test.ts`에 다음을 추가하거나 갱신한다.

- map1이 18px, 160×120, 2880×2160으로 로드되는지
- 18px map의 row 수/길이 오류
- map1에 rows와 regions가 동시에 있을 때 실패
- 시작점 또는 스폰점이 blocked일 때 실패
- unsupported cell size 오류
- 기존 36px regions 맵이 계속 로드되는지
- artwork width/height 불일치 오류

## 검증 명령

```text
npm test -- src/core/MapDefinitionLoader.test.ts
npm run build
npm run qa:art
```

## 완료 조건

loader가 map1을 typed `MapDefinition`으로 반환하고, 다른 맵에 대한 기존 검증 결과가 변하지 않는다.
