# 7.4 — 18px TerrainGrid·경로·충돌 회귀

## 목표

TerrainGrid와 이를 사용하는 충돌·경로 계층이 36px 상수를 전제로 하지 않는지 확인하고, 18px map에서 같은 API가 정확히 동작하도록 한다.

## 구현 범위

- `TerrainGrid`의 world↔cell 변환, cell bounds, world bounds가 cell size에 비례하는지 확인한다.
- AABB, circle, oriented rectangle footprint가 18px 경계를 기준으로 차단되는지 확인한다.
- segment raycast가 얇은 blocked tile을 건너뛰지 않고 첫 차단 cell을 반환하는지 확인한다.
- `TerrainPathfinder`의 8방향 이동, 대각선 corner cutting 금지, radius-aware 통과 검사를 18px grid에서 확인한다.
- `Vehicle`, `Enemy`, `Projectile`, `Game`에 남은 36px literal 또는 cell-size 가정을 제거한다.
- tank footprint가 18px tile 여러 개를 차지할 때도 기존 회전·벽면 이동 계약을 유지한다.
- 불필요한 새 physics/navmesh/cache는 추가하지 않는다.

## 테스트

`TerrainGrid.test.ts`와 `TerrainPathfinder.test.ts`에 다음 케이스를 추가한다.

- 18px worldToCell 경계와 음수/월드 밖 판정
- 한 blocked tile의 AABB·circle·oriented rect 충돌
- 18px 한 칸을 통과하는 segment raycast
- 대각선 blocked corner 통과 금지
- standard/tanker radius에 따른 좁은 통로 통과/실패
- 큰 frame delta에서 thin tile을 건너뛰지 않는 이동/충돌
- 시작점과 끝점은 열려도 중간 회전에서 blocked가 되는 경우

## 검증 명령

```text
npm test -- src/core/TerrainGrid.test.ts src/core/TerrainPathfinder.test.ts
npm test
npm run build
```

## 완료 조건

18px map에서 판정 정확도가 높아지고, 기존 36px 맵의 관련 test가 함께 통과한다. 실패가 map1 데이터 문제가 아니라 공통 계층 문제라면 이 단계에서 수정한다.
