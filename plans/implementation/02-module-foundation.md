# 02. 모듈 기반 정리

## 목표

모든 모듈이 동일한 기본 상태와 생명주기를 갖도록 정리하고, 3x3 격자에 안전하게 설치·업그레이드할 수 있게 한다.

## 선행 조건

- [01 플레이 가능한 게임 루프](01-playable-loop.md) 완료

## 작업 대상

- `src/entities/Module.ts`
- `src/entities/Vehicle.ts`
- `src/ui/HUDManager.ts`
- `src/core/Game.ts`

## 작업 순서

1. `BaseModule`에 `maxHp`, `currentHp`, 활성 여부와 피해 처리 함수를 추가한다.
2. HP가 0인 모듈은 `update`에서 기능을 수행하지 않도록 한다.
3. 코어의 HP 처리도 공통 피해 흐름을 사용하되, 코어 파괴는 게임 패배로 연결한다.
4. 모듈 타입을 현재 구현 타입과 시스템 문서의 분류에 맞춰 유지한다.
5. 격자 범위·점유 여부·코어 위치 검사를 `Vehicle`의 단일 경로로 모은다.
6. 설치 실패, 자원 부족, 이미 점유된 칸을 HUD에서 구분할 수 있게 한다.
7. 업그레이드 비용과 레벨 증가를 유지하고, HP 증가 여부는 모듈별 규칙으로 명시한다.
8. 선택 모듈의 이름·레벨·HP를 정보 패널에 표시한다.

## 완료 기준

- 모든 모듈이 HP를 갖고 0 HP에서 비활성화된다.
- 비활성화된 무기는 사격하지 않고, 비활성화된 생산기는 자원을 만들지 않는다.
- 코어는 중심 칸에만 존재하며 중복 설치할 수 없다.
- 빈 칸에만 모듈을 설치할 수 있고, 설치 비용을 지불하지 못하면 상태가 변하지 않는다.
- 업그레이드 후 성능과 비용이 일관되게 갱신된다.

## 검증

- 모듈 HP를 임시로 0으로 만든 뒤 사격·생산 중단을 확인한다.
- 코어 칸과 점유 칸에 설치를 시도한다.
- 자원이 부족한 상태에서 설치·업그레이드 실패를 확인한다.
- 각 모듈을 2회 이상 업그레이드하고 비용·레벨 표시를 확인한다.
- `npm run build`
