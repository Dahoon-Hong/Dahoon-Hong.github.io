# 18. 협곡 기지 방어와 지하 광산 자동화

상태: 기초 계획 · 구현 전 세부 규칙 결정 필요
기준 브랜치: `defence2`

## 목적

하나의 미션을 협곡 지상과 광산 지하로 나눈다. 지상에서는 협곡에서 생성된 적이 기지로 진입하고, 플레이어는 땅에 방어 시설을 건설해 기지를 지킨다. 지하에서는 광물을 채굴·운송·가공·저장하는 공장을 자동화한다. 갱도는 지하 생산품을 지상에 공급한다. `Tab`으로 표시·조작할 층을 바꾸며, 보이지 않는 층도 계속 진행한다.

이 계획은 차량을 조종하는 기존 게임 콘셉트를 계승하지 않는다. 차량·차체·차량 Core·차량 격자는 새 미션의 플레이어 또는 방어 목표가 아니다. 기존 코드에서 재사용할 대상은 공격 모듈의 정의와 조준·발사·투사체·피해 동작 등 유효한 전투 기능이다.

## 요구사항 및 범위

### 확정된 방향

- 지상에는 협곡 맵, 적 생성 지점, 기지, 건설 가능한 땅과 방어 시설이 있다. 적은 지상에서 생성되어 기지로 향한다.
- 기존 direct/arc 공격 모듈을 지상 방어 시설로 활용한다. 설치 위치는 차량 격자가 아니라 벽·언덕을 제외한 설치 가능한 땅이다.
- 바리케이드를 지상 설치물로 추가한다. 실제 이동·피해 판정에 참여하며 장식용 장애물로 대체하지 않는다.
- 지하에는 광물 원천, 채굴기, 운송 경로, 가공기, 저장소를 연결하는 자동화 생산 흐름이 있다.
- 갱도는 지하 출력과 지상 입력을 잇는 물류 연결점이다.
- `Tab`은 지상과 지하의 표시·건설·관리 대상을 전환한다. 전환 자체가 엔티티를 이동시키지 않는다.
- 두 층의 전투·생산·물류는 활성 화면과 무관하게 진행한다. 전체 일시정지 중에는 자동 진행을 멈추고, 기존 01 규칙에 따라 설치·업그레이드는 허용한다.

### 기존 구현에서 변경할 경계

- 현재 `Game`의 단일 맵·지형·카메라·적·자원 상태를 미션 공통 상태와 층별 상태로 나눈다. `activeLayer`는 표시와 입력 대상만 고른다.
- 현재 맵 데이터의 차량 시작 위치와 차량 도달 경로 검증은 새 미션의 기지·적 스폰·갱도·설치 가능 영역 계약으로 교체하거나 새 형식과 분리한다.
- 현재 적의 차량 추적·접촉 피해와 차량 Core 기반 패배를 기지 목표·기지 피해 규칙으로 교체한다.
- 현재 공격 모듈은 탱크별 정의, 차량 `CombatGrid`, 차량 자원·업그레이드에 결합되어 있다. 지상 설치의 점유·구매·강화·탄약 공급은 별도 계약으로 두고 전투 동작만 필요한 만큼 재사용한다.
- 현재 `VehicleSystems`의 자동 생산과 차량 `ResourceStorage`는 지하 공장의 설계 기준이 아니다. 지하의 채굴·운송·가공·버퍼·저장 책임과 지상의 수신·소비 책임을 분리한다.
- 구현 전에 `game-design.md`, `plans/concept.md`, `plans/system.md`의 차량 중심·공장 제외 방향을 새 콘셉트와 맞춘다. 과거 계획은 코드 재사용 참고 자료일 뿐 새 요구사항의 근거로 삼지 않는다.

### 구현 전에 결정할 항목

- 기지의 체력·파괴 시 결과, 미션 성공 조건, 적 웨이브·생성 규칙.
- 지상 방어 시설의 크기·설치 비용·철거·강화·탄약 공급과 기존 공격 모듈 중 재사용할 범위.
- 바리케이드의 내구도·설치 가능 위치, 적의 우회 또는 공격, 모든 경로를 막는 배치의 허용 여부.
- 광물 종류, 최소 제조식, 채굴·가공 시간, 운송 방향·속도·용량, 버퍼와 저장소의 가득 참 처리.
- 갱도로 보낼 품목·전달 우선순위·용량·수신 저장소. 지상과 지하 중 어느 쪽이 각 자원을 소유하는지.
- 협곡과 광산의 배치·아트, 적 스폰·기지·갱도 좌표, 기존 캠페인과의 연결 방식.

위 값은 이 기초 계획에서 임의로 확정하지 않는다. 각 구현 단계의 상세 계획을 시작하기 전에 필요한 결정을 기록한다.

## 구조 원칙

- 하나의 미션이 `surface`와 `underground`의 맵·지형·엔티티·건설 상태를 보유한다. 갱도와 전체 일시정지·승패 상태는 미션이 관리한다.
- 층별 카메라 위치와 건설 상태를 보존한다. `Tab` 입력은 게임 화면에서만 한 번 처리하고 브라우저 기본 포커스 이동과 충돌하지 않도록 한다.
- 지상 공격 모듈은 설치 지점의 세계 좌표에서 기존 조준·발사 동작을 사용한다. 차량 격자나 차량 위치를 전제로 하는 부분은 지상 시설 계약에 맞춘다.
- 지하 생산은 `광물 → 채굴 → 운송 → 가공 → 저장 → 갱도`의 최소 경로부터 연결한다. 입력 부족·출력 공간 부족·경로 단절 시 자원 손실이나 중복 생성이 없어야 한다.
- 보이는 벽·언덕은 완성 맵 이미지와 같은 좌표의 숨겨진 지형 윤곽으로 판정한다. 바리케이드는 플레이어가 설치한 게임플레이 구조물로 관리한다.

## 구현 순서

### 18.1 방향 문서와 최소 데이터 계약

- 차량을 플레이어로 두던 방향 문서를 새 기지 방어·광산 자동화 콘셉트로 갱신한다.
- 지상·지하 맵, 기지·스폰·갱도 좌표, 설치 가능 영역, 층별 상태와 전체 승패·일시정지 계약을 정의한다.
- 첫 플레이 가능 경로에 필요한 적·무기·광물·생산품·갱도 전달 및 바리케이드 규칙을 결정한다. 수치와 아트는 콘텐츠 상세 계획에 기록한다.

### 18.2 두 층의 로드·전환·동시 진행

- 한 미션에서 지상·지하 맵을 함께 로드하고 두 층의 상태를 유지한다.
- `Tab`으로 표시·입력 대상을 바꾸되 비활성 층의 시뮬레이션은 멈추지 않는다.
- 전체 일시정지는 두 층의 자동 진행을 함께 멈춘다. 메뉴·입력 포커스와 충돌하지 않는 전환 규칙을 적용한다.

### 18.3 지상 기지 방어의 최소 경로

- 협곡 스폰의 적이 기지로 이동해 기지를 공격하고 기지 상태가 승패 판정에 반영되게 한다.
- 설치 가능한 땅에 기존 direct/arc 공격 모듈을 배치하고 적 조준·발사·피해를 확인한다.
- 벽·언덕·경계 밖·기존 구조물 점유 칸은 설치를 거부한다. 지하 공급 전에는 상세 계획에 정한 초기 자원으로 발사를 검증한다.

### 18.4 지하 공장의 최소 생산 경로

- 광물 원천 하나에서 채굴·운송·가공·저장까지 이어지는 최소 흐름을 만든다.
- 각 기계와 경로의 입력·출력·용량을 분리하고 입력 부족·출력 막힘·저장 공간 부족을 처리한다.
- 생산과 물류는 지하 화면을 보지 않을 때도 진행하고 일시정지 중에는 멈춘다.

### 18.5 갱도 공급과 지상 소비

- 지하 저장·출력과 지상 수신 저장소를 갱도로 연결한다.
- 전달 전후의 총량을 보존하고 수신 공간 부족·연결 단절·일시정지 시 전송을 보류한다.
- 전달된 생산품이 지상 방어의 정해진 소비처에 실제로 사용되는 한 경로를 완성한다.

### 18.6 바리케이드와 적 경로

- 바리케이드를 지상 설치물로 추가하고 충돌·내구도·피해를 연결한다.
- 18.1에서 결정한 우회·공격·완전 차단 규칙에 따라 설치 유효성과 적 경로 갱신을 구현한다.

### 18.7 맵 아트·통합

- 협곡과 광산 이미지, 지형 윤곽, 설치 가능 영역, 스폰·기지·갱도 좌표를 맞춘다.
- 두 층 전환, 비활성 층 진행, 기지 방어, 광산 생산, 갱도 공급, 바리케이드, 일시정지를 하나의 미션에서 검증한다.

기능 구현 단계의 완료 전에는 해당 plan worktree에서 실행한 runtime의 정확한 URL·port와 required 시나리오를 `integration-tester`에 전달한다. tester는 별도 서버 없이 한 번의 bounded 실행으로 최종 결과를 반환한다. Required가 `FAIL` 또는 `BLOCKED`이면 완료·commit을 보류하고 재현 조건을 기록한다. 문서만 바꾼 단계는 `git diff --check`와 링크·명령어를 확인한다.

## 계획 완료 기준

- 새 콘셉트에 차량 조작·차량 Core·차량 격자가 플레이어 또는 목표로 남지 않는다.
- 적의 기지 공격과 지상 설치형 공격 모듈·바리케이드가 플레이 가능하다.
- 지하의 채굴·운송·가공이 갱도를 거쳐 지상 방어의 소비처에 연결된다.
- `Tab` 왕복과 비활성 층 진행·전체 일시정지가 상태 손실 없이 동작한다.
- 각 상세 계획에 요구사항·범위·사용자 결정 사항·Required runtime QA가 기록되고 통합 시나리오가 통과한다.
