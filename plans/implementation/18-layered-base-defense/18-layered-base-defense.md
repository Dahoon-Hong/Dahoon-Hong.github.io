# 18. 지상·지하 기지 방어와 공장 자동화

상태: 기초 계획 · 설계 승인됨 · 구현 전 세부 결정 필요
기준 브랜치: `defence2`

## 목적

협곡 지상에서 적의 기지 공격을 막고, 지하에서는 광산 자원을 자동 채굴·운송·가공하는 하나의 미션을 만든다. 지상과 지하는 갱도 연결 정보를 공유하고, `Tab`은 현재 조작·표시할 층을 바꾼다. 두 층은 화면에 보이지 않는 동안에도 계속 진행한다.

## 요구사항 및 범위

### 확정된 방향

- 지상은 협곡 통로, 적 스폰 지점, 플레이어 기지와 방어 시설을 갖춘 디펜스 층이다.
- 적은 지상에서 생성되어 기지를 공격한다.
- 지하에는 광물 채굴, 물류 운송, 가공, 저장을 잇는 자동화 생산 흐름을 둔다.
- 갱도는 두 층을 연결하며 지하 생산품을 지상으로 보낼 수 있어야 한다.
- `Tab`은 지상·지하 층의 표시와 조작 대상을 전환한다. 두 층의 시뮬레이션은 계속 진행한다.
- 기존 direct/arc 공격 모듈의 전투 동작을 재사용하고, 지상에서는 벽이 아닌 설치 가능한 땅에 배치한다.
- 바리케이드 모듈을 추가한다. 이동 차단, 내구도, 적의 우회·공격 규칙은 세부 설계 단계에서 확정한다.
- 일시정지는 기존 규칙을 따른다. 전투·적 이동·자동 생산·수집은 멈추고, 모듈 설치와 업그레이드는 허용한다.

### 현재 구현과 설계 경계

- 현재 런타임은 한 번에 하나의 `TerrainGrid`와 지역을 처리한다. 지상·지하 상태를 각각 보존하고 함께 갱신하는 경계가 필요하다.
- 현재 전투 모듈 설치는 차량 `CombatGrid`에 한정된다. 지상 설치는 별도 배치·점유 판정을 두고, 무기 정의와 발사 동작을 재사용한다.
- 현재 생산은 `VehicleSystems`와 차량의 단일 `ResourceStorage` 중심이다. 지하 공장은 이를 억지로 차량 내장 시스템으로 확장하지 않고, 노드·운송 경로·기계·버퍼의 별도 책임으로 설계한다.
- 현재 적은 차량 Core를 목표로 한다. 지상 기지의 목표 체력, 패배 조건, 차량과 기지의 관계를 새 계약으로 정한다.
- 현재 `game-design.md`는 공장 자동화를 제외 범위로 기록한다. 구현 전에 `game-design.md`, `plans/concept.md`, `plans/system.md`를 새 방향과 일치시킨다.

### 범위에서 확정하지 않을 값

맵의 구체적인 협곡 윤곽·아트, 기지 체력과 패배 조건, 적 웨이브와 수치, 광물 종류와 제조식·시간, 물류 운송량과 막힘/가득 참 처리, 바리케이드 크기·체력·행동은 임의로 채우지 않는다. 콘텐츠 세부 계획 전에 사용자와 확정한다.

구현 전 결정 목록에는 차량이 갱도를 실제로 이동하는지, 바리케이드 앞에서 적이 우회하는지 공격하는지, 지상 방어 모듈의 설치 비용을 어떤 자원에서 지불하는지, 갱도에서 어떤 자원과 우선순위로 전달하는지도 포함한다.

## 구조 제안

- 하나의 미션 상태에 지상과 지하의 맵, 지형, 엔티티, 생산 상태를 각각 둔다. `activeLayer`는 표시와 플레이어 입력에 사용할 층을 고르고, 갱신 루프는 두 층을 모두 처리한다.
- 층별 카메라 위치와 엔티티 상태를 전환 뒤에도 보존한다. 일시정지 상태는 미션 전체에 적용한다.
- 갱도는 지상·지하의 연결 위치 쌍으로 표현한다. 화면 전환과 실제 차량 이동은 서로 다른 동작으로 취급하며, 플레이어가 차량을 갱도로 이동시킬지 여부는 세부 결정으로 남긴다.
- 지상 방어 배치는 차량 격자와 별도 관리한다. 설치 판정은 설치 가능 지형, 경계, 기존 구조물 점유를 확인한다. 무기 동작과 데이터는 기존 공격 모듈 계약을 우선 재사용한다.
- 지하 생산 흐름은 `광물 → 채굴기 → 운송 경로 → 가공기 → 저장/갱도`로 구성한다. 입력 부족, 출력 버퍼 가득 참, 막힌 경로를 명시적으로 다룬다.
- 벽과 언덕은 맵 이미지와 같은 좌표의 숨겨진 지형 윤곽으로 표현한다. 바리케이드는 실제 게임플레이 설치물로만 별도 배치하며 장식용 반복 장애물로 대체하지 않는다.

## 구현 순서

### 18.1 방향 문서와 데이터 계약

- 현재 게임 방향 문서에서 공장 자동화를 제외 대상으로 둔 내용을 새 핵심 루프와 일치시킨다.
- 지상·지하 레이어 데이터, `activeLayer`, 갱도 연결점, 층별 시뮬레이션 경계를 정의한다.
- 세부 구현에 앞서 맵 외곽·지형·스폰·기지 위치, 지하 광물·제조식, 바리케이드의 이동·피해 규칙을 확정한다.

### 18.2 두 층의 맵과 전환

- 한 미션이 지상·지하 맵 정의를 함께 로드하도록 확장한다.
- `Tab` 입력은 활성 층과 해당 층의 표시·조작 대상을 전환하고 기존 층 상태를 보존한다.
- 화면에 보이지 않는 층의 적·생산·물류도 계속 갱신하고, 일시정지 시 두 층 모두 정지시킨다.

### 18.3 지상 기지와 방어 배치

- 기지 목표와 적의 협곡 스폰·경로·공격을 연결한다.
- 기존 공격 모듈을 설치 가능한 땅에 배치하는 지상 전용 점유·비용·유효성 규칙을 추가한다.
- 바리케이드 설치와 지형 충돌, 적 경로의 우회 또는 파괴 동작을 정의하고 구현한다.
- 기존 무기의 탄약 소비·조준·발사 규칙이 지상 설치에서도 동일하게 동작하도록 연결한다.

### 18.4 지하 채굴과 생산 물류

- 광물 원천, 채굴, 가공, 출력 버퍼와 저장을 연결하는 최소 플레이 가능 생산 흐름을 만든다.
- 물류 경로의 방향·운송 속도·용량·막힘 규칙은 별도 계약으로 두고, 현재 차량 Rail 동작과 혼합하지 않는다.
- 일시정지 시 채굴·가공·운송을 모두 멈춘다.

### 18.5 갱도를 통한 층간 물류

- 갱도 연결점에서 지하 출력과 지상 입력을 전달한다.
- 수용 공간 부족, 연결 단절, 일시정지 상황에서 자원 손실이나 중복 생성이 없어야 한다.
- 지상 공격 모듈의 탄약 또는 건설 재료 중 어떤 자원을 우선 연결할지 경제 규칙에 따라 확정한다.

### 18.6 맵 정렬과 전체 통합

- 협곡 이미지와 숨겨진 지형 윤곽, 스폰·기지·갱도 좌표를 맞춘다.
- 두 층 왕복, 비활성 층 진행, 지상 방어, 지하 생산, 갱도 전달, 일시정지를 하나의 런타임 흐름으로 검증한다.
- 필수 런타임 검증은 해당 구현 worktree에서 실행한 서버의 정확한 URL·port를 전달받은 `integration-tester`가 bounded 단일 실행으로 수행한다.

## 필수 검증 시나리오

각 fixture는 개발용 runtime에서만 사용할 수 있게 등록한다. 아래 식별자는 계획 단계 이름이며, 해당 하위 구현 계획에서 fixture 사전조건과 observer 필드를 구현 세부에 맞게 확정한다.

| ID | Required | Runtime fixture 및 사전조건 | 관측값 | 통과 기준 |
| --- | --- | --- | --- | --- |
| L18-1 | Yes | `l18-layer-switch`: 양쪽 층에 차량/구조물과 생산 상태가 있는 상태로 시작 | `activeLayer`, 각 층의 엔티티 ID·좌표·생산 상태 | `Tab` 왕복 뒤 상태가 보존되고 엔티티가 추가·삭제·중복되지 않는다. |
| L18-2 | Yes | `l18-background-tick`: 한 층에는 생존 적, 다른 층에는 입력이 충분한 생산기를 둔다. 유효한 설치 칸·설치 모듈·업그레이드 대상과 양쪽 비용을 낼 자원을 준비한다. 활성 층을 바꿔 고정된 업데이트 구간을 진행한 뒤 전체 일시정지도 실행 | 양 층의 적 좌표/HP, 생산 진행률·버퍼·저장량, 설치 결과·셀, 업그레이드 레벨, 자원 잔액, pause 전후 값 | 비활성 층도 적과 생산이 진행한다. 일시정지 구간에는 양 층의 자동 진행이 없고, 유효한 설치·업그레이드는 성공하며 정해진 비용만 차감된다. |
| L18-3 | Yes | `l18-ground-placement`: 열린 칸, 벽/언덕 칸, 경계 밖, 기존 구조물 점유 칸을 각각 준비 | 설치 결과, 점유 셀, 자원 잔액 | 열린 칸에만 설치된다. 거부된 입력은 점유와 자원 잔액을 바꾸지 않는다. |
| L18-4 | Yes | `l18-barricade-route`: 협곡 스폰에서 기지까지 경로를 두고 그 경로에 바리케이드를 배치한다. 실행 전 18.1에서 바리케이드의 적 대응 규칙 하나를 확정한다. | 적 위치·경로·공격 대상, 바리케이드 HP, 기지 HP | 확정된 한 가지 규칙과 적의 경로 결과가 일치한다. 규칙이 확정되지 않았으면 실행하지 않고 `BLOCKED`로 기록한다. |
| L18-5 | Yes | `l18-ground-combat`: 사거리 안에 적을 두고 direct/arc 공격 모듈에 발사 가능한 탄약을 준비 | 조준 대상, 발사체/피해, 탄약 잔액 | 기존 모듈 규칙대로 발사·피해·탄약 차감이 발생하며, 일시정지 중에는 바뀌지 않는다. |
| L18-6 | Yes | `l18-factory-flow`: 광물 원천, 채굴기, 연결된 운송 경로, 입력이 맞는 가공기와 빈 출력 저장 공간을 준비 | 광물·운송량·입력/출력 버퍼·저장량 | 광물이 한 생산 경로를 따라 이동해 가공품으로 저장된다. |
| L18-7 | Yes | `l18-factory-backpressure`: 출력 저장 공간을 가득 채우거나 운송 경로를 막은 상태로 시작 | 기계 입력·출력 버퍼, 경로 적재량, 저장량 | 확정된 막힘 규칙대로 생산이 대기·정지하며 자원 손실과 중복 생성이 없다. |
| L18-8 | Yes | `l18-tunnel-transfer`: 지하 전달 가능한 출력과 지상 수신 저장 공간을 준비한 뒤 정상 전달·용량 부족·일시정지를 각각 확인 | 양쪽 전후 수량, 전송 버퍼, pause 상태 | 전송 전후 수량이 보존되고 중복·손실이 없다. 수신 공간이 없거나 일시정지 중에는 전달되지 않는다. |
| L18-9 | Yes | `l18-map-alignment`: 제작 맵, 지형 경계, 스폰·기지·갱도 위치가 모두 로드된 상태 | 이미지 좌표와 terrain collision/path query 결과 | 보이는 벽·언덕 및 핵심 좌표가 판정 위치와 일치하고, 스폰에서 기지로 가는 확정된 경로가 유효하다. |

계획 구현 완료 시 필수 시나리오는 실제 runtime에서 확인한다. 호출 전 현재 plan worktree 절대 경로, 실제 URL·port, 고유 `runtimeId`, 변경사항, required 시나리오와 timeout을 integration-tester에 전달한다. tester는 1회 bounded 실행으로 결과를 반환한다. 대상 시나리오가 `FAIL` 또는 `BLOCKED`이면 완료·commit을 보류하고 재현 조건과 원인을 남긴다. 범위 밖은 `SKIP-N/A`, 환경상 불가능한 검증만 사유와 영향 범위를 적은 `SKIP-ENV`로 기록한다.

## 계획 완료 기준

- 두 층의 상태·시뮬레이션·전환 경계가 명시되어 있다.
- 지상 기지 방어, 지하 생산, 갱도 물류의 구현 의존 순서와 책임 경계가 명시되어 있다.
- 지면 설치와 바리케이드가 벽/언덕 지형 및 적 경로와 상호작용하는 검증 기준이 있다.
- 미확정 밸런스·아트·콘텐츠 입력은 사용자 결정 항목으로 남아 있으며 추측값이 없다.
- 이후 각 하위 단계의 상세 구현 계획에는 요구사항, 예상 변경 범위, 필수 runtime QA 시나리오를 구체화한다.
