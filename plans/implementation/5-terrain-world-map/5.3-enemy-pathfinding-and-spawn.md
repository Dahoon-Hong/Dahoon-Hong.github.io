# 5.3 적 A* 경로 탐색과 스폰

## 목표

적이 map 내부의 유효한 spawn cell에서 생성되고, 통과 불가 지형을 뚫지 않으면서 8방향 A* 경로로 움직이는 구조를 만든다.

## 구현 범위

### A* 구현

- 새 `TerrainPathfinder` 또는 동등한 pure helper를 추가한다.
- `enemy`가 통과 가능한 cell만 후보로 사용한다.
- 직교 이동 cost 10, 대각선 cost 14와 octile heuristic을 사용한다.
- 대각선 양옆의 직교 cell 중 하나라도 막히면 해당 대각선을 제외한다.
- standard와 tanker의 radius를 반영해 cell 중심에 놓인 footprint가 언덕과 겹치지 않을 때만 통과 가능하게 한다.
- 결과는 시작 cell을 제외한 cell center waypoint 목록으로 반환한다.
- 같은 방향으로 연속된 waypoint만 합치고 추가 spline/navmesh smoothing은 하지 않는다.

### Enemy runtime 상태

- 적은 현재 path, waypoint index, 마지막 target cell, repath timer를 가진다.
- 탱크가 다른 terrain cell로 이동했거나 path가 무효해졌을 때 재탐색한다.
- 적 하나는 최대 0.25초마다 한 번 재탐색한다.
- 생성 순서에 따라 최초 timer offset을 달리해 같은 frame의 일괄 계산을 피한다.
- path가 없으면 정지하고 다음 interval에 다시 시도하며 순간이동하거나 terrain을 무시하지 않는다.
- 마지막 waypoint 이후 기존 grid contact damage 흐름으로 이어진다.

### Spawn 전환

- `WaveManager`의 world 밖 random edge spawn을 제거한다.
- 현재 map의 enemy spawn cell 목록을 받아 고정 순서 또는 순환 순서로 사용한다.
- spawn cell의 중심을 적 시작 좌표로 사용한다.
- map loader는 각 spawn에서 초기 tank start까지 enemy path가 존재하는지 확인한다.
- spawn이 유효하지 않으면 적을 생성한 뒤 보정하지 않고 map validation에서 실패시킨다.

### 테스트

- 열린 grid의 최단 경로
- 벽을 돌아가는 경로
- 협로와 교차로
- 대각선 corner cutting 거부
- standard는 통과하지만 tanker radius에는 좁은 경로
- 경로가 없는 map
- 탱크 target cell 변경 후 재탐색
- 동일 frame 재탐색 분산
- map-defined spawn 순서

## 완료 기준

- standard와 tanker가 자신의 radius로 통과 가능한 경로만 사용한다.
- 적이 언덕을 통과하거나 막힌 모서리를 대각선으로 자르지 않는다.
- 탱크가 이동하면 제한된 주기로 새 경로를 찾는다.
- 모든 map spawn이 초기 tank 위치에 도달 가능한지 로드 시 검증된다.
- 기존 웨이브 수, spawn interval, contact damage 규칙이 유지된다.
- `npm test`와 `npm run build`가 성공한다.

## 수동 QA

1. 적이 직선 벽을 만나 우회하는지 확인한다.
2. 여러 적이 동시에 생성될 때 눈에 띄는 frame hitch가 없는지 확인한다.
3. 탱크가 교차로 반대편으로 이동할 때 적이 새 경로를 선택하는지 확인한다.
4. tanker가 너무 좁은 길에 끼지 않고 다른 길을 선택하는지 확인한다.
5. pause 후 재개했을 때 path index와 repath timer가 정상 이어지는지 확인한다.
