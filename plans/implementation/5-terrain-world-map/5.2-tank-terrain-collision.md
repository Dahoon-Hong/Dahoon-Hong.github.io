# 5.2 탱크 지형 충돌

## 목표

탱크가 연속 좌표 이동을 유지하면서 `tank` 차단 terrain cell과 월드 경계를 통과하지 못하게 하고, 막힌 한 축을 따라 자연스럽게 미끄러지도록 한다.

## 선행 조건

- [5.1 지형 데이터 계약과 TerrainGrid](5.1-terrain-data-and-grid.md)
- [Plan 5 설계 명세](../../../docs/superpowers/specs/2026-09-07-plan-26-terrain-world-map-design.md)

## 구현 범위

### 이동 후보 계산

- `Vehicle.update()`가 단순 width/height 대신 현재 `TerrainGrid` 또는 최소 collision context를 받게 한다.
- 입력 vector와 speed로 전체 후보 이동량을 계산한다.
- 현재 3×3 tank grid와 tile size에서 axis-aligned movement footprint를 계산한다.
- X축 후보를 먼저 검증하고 통과 가능하면 적용한 뒤 Y축 후보를 검증한다.
- 한 축이 거부돼도 다른 축은 적용해 벽면 이동을 허용한다.
- 이동 후 기존 facing과 4-frame animation 갱신은 유지한다.

### 충돌 안정성

- world 밖은 blocked terrain처럼 처리한다.
- 큰 `dt`에서도 한 번에 얇은 언덕을 건너뛰지 않도록 이동 구간을 terrain cell 절반 이하의 step으로 나누거나 동등한 swept check를 사용한다.
- 탱크가 충돌 cell 안으로 들어간 상태를 좌표 clamp로 숨기지 않는다.
- 잘못된 시작 위치는 5.1 loader validation에서 거부하고 runtime에서 임의 teleport하지 않는다.
- pause와 terminal state에서는 기존대로 이동과 collision update를 실행하지 않는다.

### Camera와 입력 회귀

- map 크기 기반 world bounds에서 Camera clamp가 유지되는지 확인한다.
- screen/world 좌표 변환과 module drag 입력은 tank terrain collision의 영향을 받지 않게 한다.
- tank가 언덕에 막혀도 Camera는 확정된 실제 tank 위치만 따라가게 한다.

### 테스트

- 열린 cell에서 네 방향/대각선 이동
- 직선 언덕 벽 정면 충돌
- 대각선 입력 중 한 축만 막힌 벽면 이동
- world 네 변 경계
- 높은 속도/최대 frame `dt`에서 한 cell 벽 관통 방지
- 시작 cell validation 실패

## 변경 대상

- `src/entities/Vehicle.ts`
- `src/core/Game.ts`
- `src/core/TerrainGrid.ts`
- `src/core/Camera.ts`가 필요할 경우 map bounds 연결부
- Vehicle/TerrainGrid test 파일

## 완료 기준

- 탱크가 `hill` cell과 world 밖으로 이동하지 않는다.
- 대각선 입력으로 벽을 밀 때 열린 축을 따라 이동한다.
- 이동 방향, sprite animation, module/grid rotation이 회귀하지 않는다.
- collision에 실패한 frame에서 Camera가 가짜 후보 위치를 따라가지 않는다.
- `npm test`와 `npm run build`가 성공한다.

## 수동 QA

1. 언덕의 네 면에 정면으로 접근해 시각적 경계에서 멈추는지 확인한다.
2. 벽을 향한 대각선 입력으로 벽면을 따라 이동하는지 확인한다.
3. 좁은 길 입구에서 빠르게 방향을 바꿔도 끼이거나 순간 이동하지 않는지 확인한다.
4. PAUSED 중 이동과 Camera 추적이 진행되지 않는지 확인한다.
