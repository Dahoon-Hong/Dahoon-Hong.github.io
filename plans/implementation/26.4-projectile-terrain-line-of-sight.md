# 26.4 탄환 지형 충돌과 시야 차단

## 목표

언덕 뒤의 적을 자동 조준 후보에서 제외하고, 이미 발사된 direct/arc 탄환이 한 frame에 지형을 건너뛰지 않도록 첫 terrain 충돌점에서 소멸시킨다.

## 구현 범위

### Terrain raycast

- `TerrainGrid`에 world 선분의 시작점과 끝점을 받는 raycast를 완성한다.
- 선분이 지나는 cell을 순서대로 검사하고 `projectile` 차단 cell의 첫 hit만 반환한다.
- 반환값은 최소한 hit cell, world hit point, 진행 비율을 포함한다.
- 시작점이 차단 cell 안이면 진행 비율 0의 hit로 처리한다.
- world 밖 진입은 차단으로 처리한다.
- 이미지 alpha나 hill edge 그림은 raycast에 사용하지 않는다.

### 자동 조준 line-of-sight

- 사격각과 range를 통과한 적 후보에 module 중심 → 적 중심 terrain raycast를 적용한다.
- 중간에 projectile 차단 지형이 있으면 후보에서 제외한다.
- 보이는 후보가 없으면 탄약을 소비하지 않고 cooldown을 시작하지 않는다.
- 기존 target 우선순위, fire arc, damage, ammo cost는 유지한다.
- `CombatModule`이 map data를 직접 알지 않도록 `hasLineOfSight` callback 또는 작은 query interface를 update context로 전달한다.

### 실제 탄환 충돌

- 매 frame 이전 위치와 다음 위치 사이를 raycast한다.
- 적 충돌과 terrain 충돌이 모두 발생할 수 있으면 진행 비율이 더 작은 첫 충돌만 적용한다.
- terrain이 먼저면 적 피해를 적용하지 않고 projectile을 소멸시킨다.
- 기존 hit effect 체계를 재사용해 작은 terrain impact effect를 표시한다.
- direct와 arc 모두 현재는 같은 projectile 차단 규칙을 사용한다.
- 특정 무기의 관통이나 곡사 예외는 추가하지 않는다.

### 테스트

- 수평/수직/대각선 raycast
- 여러 hill을 통과하는 선분의 첫 hit
- 한 frame에 한 cell보다 멀리 이동하는 projectile
- 적보다 앞선 terrain과 적보다 뒤의 terrain
- 언덕 뒤 적만 있을 때 ammo/cooldown 불변
- 같은 range/fire arc 안에서 보이는 적과 가려진 적이 함께 있을 때 보이는 적 선택
- direct/arc의 동일한 차단 적용

## 완료 기준

- 언덕 뒤 적은 자동 조준되지 않는다.
- 가려진 적만 있으면 탄약과 cooldown이 변하지 않는다.
- direct와 arc 탄환이 첫 `hill` cell에서 소멸한다.
- 큰 frame 이동에서도 얇은 언덕을 관통하지 않는다.
- terrain과 적 중 더 가까운 첫 충돌만 결과에 반영된다.
- 기존 사격각 preview와 공격 방향이 회귀하지 않는다.
- `npm test`와 `npm run build`가 성공한다.

## 수동 QA

1. 언덕 뒤 적이 있을 때 무기가 대기 상태인지 확인한다.
2. 적이 언덕 옆으로 나오는 순간 정상 조준·발사하는지 확인한다.
3. 이동 중 발사체가 언덕 모서리를 시각적으로 뚫지 않는지 확인한다.
4. direct와 arc를 각각 언덕 방향으로 발사해 동일한 차단을 확인한다.
5. PAUSED 중 탄환과 cooldown이 진행되지 않는지 확인한다.
