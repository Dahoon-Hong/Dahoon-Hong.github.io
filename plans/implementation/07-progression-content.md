# 07. 진행과 콘텐츠

## 현재 적용 계획

06.5 재설계 결과를 기반으로 코어 웹 선택형 업그레이드와 지역·행성 진행을 추가한다. 실행 순서는 `06.5 → 07 → 99 → 100`으로 유지한다.

- 탱크의 기본 격자, 코어 칸, 초기 전투 배치는 `src/data/tanks/<tankId>/module.json`으로 관리한다.
- 코어를 포함한 내장 시스템과 전투 모듈의 수치·업그레이드 선택지는 각 모듈 JSON의 `upgradeTree`로 관리한다.
- 코어는 숫자 레벨업이나 별도 구매 버튼을 사용하지 않는다. `core.json`의 `UPGRADE WEB`에서 성능 또는 격자 확장 선택지를 고른다.
- 코어 업그레이드는 `maxHp` 등 성능 수치를 바꿀 수 있고, 허용된 격자 확장 효과로 현재 격자를 넓힐 수 있다. 확장 시 기존 모듈의 좌표와 선택 상태를 보존한다.
- 격자의 초기 크기와 코어 위치는 탱크 콘텐츠 정의가 결정하며, 코어 선택지는 해당 기본값을 확장할 뿐 탱크 정의를 교체하지 않는다.
- 지역·행성 진행은 코어 업그레이드와 분리한 메모리 상태로 관리한다. 같은 행성의 지역 전환은 전투 모듈·업그레이드·자원을 유지하고, 새 행성 진입은 초기 상태를 적용한다.
- 1차 구현은 브라우저 영속 저장과 복잡한 세이브 슬롯을 추가하지 않는다.

- 탱크·모듈 JSON 로더와 업그레이드 웹 동작
- 전투 모듈 다중 칸 배치와 일시정지·재시작 흐름

## 작업 순서

1. 코어의 `upgradeTree`를 내장 시스템과 같은 웹 선택형 흐름으로 사용하고, 성능 수치와 격자 확장 효과를 허용한다.
2. 코어 격자 확장 선택 시 `3x3 → 5x5`가 되도록 하며, 기존 모듈 위치·점유·선택 상태를 보존한다. 확장 전후의 설치·경계·렌더링 기준을 동일하게 유지한다.
3. 격자 확장 효과는 `add` 방식의 제한된 `gridColumns`·`gridRows` 통계만 허용하고, 임의 스크립트나 격자 축소는 지원하지 않는다.
4. 일반 적·탱커 적의 수치와 등장 시점을 지역 설정 데이터로 분리한다.
5. 지역별 웨이브 수·적 수·증가 규칙을 설정 데이터로 관리한다.
6. 지역 클리어와 행성 클리어를 구분하고, 지역 종료 시 다음 지역 또는 다음 행성 전환 버튼을 제공한다.
7. 같은 행성의 다음 지역에서는 전투 모듈·코어 및 시스템 업그레이드·보유 자원을 유지하고, 웨이브·적·픽업·코어·전투 모듈의 런타임 상태만 새로 시작한다.
8. 새 행성 진입 시 탱크의 초기 전투 배치·업그레이드 선택·초기 자원·초기 픽업으로 재설정한다.
9. 재시작은 현재 지역의 런을 초기화하며, 행성 진행 위치는 유지한다.
10. 저장이 필요해질 때까지 브라우저 영속 저장은 추가하지 않는다.

## 완료 기준

- 코어가 일반 내장 시스템과 동일한 웹 선택형 업그레이드로 표시되고 동작한다.
- 코어 성능 업그레이드와 격자 확장 선택지가 비용·효과·분기 잠금 규칙을 따른다.
- 격자 확장 후 기존 모듈 위치와 선택 상태가 유지되고 새 칸에 전투 모듈을 설치할 수 있다.
- 지역마다 적 구성과 웨이브 수가 설정에 따라 달라진다.
- 지역 클리어 후 같은 행성의 다음 지역으로 이동할 수 있다.
- 같은 행성 전환에서 모듈·업그레이드·자원 유지 규칙이 적용된다.
- 새 행성 전환에서 초기화 규칙이 적용된다.
- 현재 지역 재시작 시 지역 런만 초기화된다.

## 검증

- 코어 웹에서 성능 노드와 `3x3 → 5x5` 확장 노드를 선택한다.
- 확장 전후 기존 전투 모듈의 anchor·footprint·선택 상태와 새 칸 설치를 확인한다.
- 확장 전후 코어 칸·금지 칸·겹침·경계 검사를 확인한다.
- 지역별 웨이브 적 구성과 탱커 등장 시점을 확인한다.
- 지역 종료 후 같은 행성에서 유지되는 항목을 확인한다.
- 새 행성 진입 후 초기화되는 항목을 확인한다.
- 재시작 후 현재 지역 런 상태와 행성 진행 위치를 확인한다.
- `npx.cmd tsc --noEmit`
- `npm.cmd run build` 또는 권한 문제가 있는 경우 대체 출력 경로 빌드
- `git diff --check`
