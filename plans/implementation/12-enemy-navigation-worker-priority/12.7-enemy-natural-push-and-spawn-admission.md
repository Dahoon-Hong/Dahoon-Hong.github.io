# 12.7 적 자연스러운 밀어내기와 spawn admission

상태: 구현 완료 (자동 검증 2026-09-14, runtime QA 대기)
상위 plan: [12. 적 시야 우선 추적 및 A* Web Worker 분리](12-enemy-navigation-worker-priority.md)
선행 구현: 현재 PR #23의 `EnemyCollisionResolver`는 임시 보정으로 간주한다.

## 목적

현재 `EnemyCollisionResolver.separate()`는 적이 겹칠 때 `x/y`를 즉시 바꾸고,
최대 8회의 pass와 여러 terrain probe로 겹침을 해소한다. 이 방식은 적이
순간이동하듯 튀고, 같은 위치에서 생성된 적이 한 프레임에 강제로 펼쳐지며,
적 수가 많아질수록 collision 계산량도 급증한다.

이 subplan에서는 적-적 충돌을 위치 보정이 아닌 짧은 push intent로 바꾼다.
spawn에서 생긴 겹침은 여러 simulation update에 걸쳐 인접 적으로 연속 전달되며,
주변이 포화되어 밀어낼 수 없는 경우에는 새 적을 만들지 않고 spawn attempt를
skip한다.

## 요구사항 및 범위

### 포함

- 적-적 겹침을 pair별 반발 방향·push 강도로 계산한다.
- collision resolver가 적-적 겹침을 해소하기 위해 `enemy.x/y`를 직접 쓰지 않는다.
- 계산된 push intent를 기존 path/local/engaged 이동 의도와 합산해 `dt`에 따라
  자연스럽게 이동시킨다.
- exact-overlap은 `navigationId` 기반의 결정론적 방향을 사용하되, 같은
  update에서 위치를 강제 분산하지 않고 다음 update들에 걸쳐 chain push한다.
- 실제 이동은 기존 `TerrainGrid.getSafeRadiusProgress()`를 통과해 벽·언덕을
  관통하지 않는다.
- `WaveManager`의 spawn 전에 지형 안전성과 주변 push 여유를 확인한다.
- push 여유가 있는 작은 겹침은 spawn을 허용하고 자연스러운 밀어내기로 처리한다.
- 모든 probe 방향이 terrain 또는 적 군집으로 막힌 포화 상태에서는 spawn하지
  않고 skip한다.
- 실제 생성 수와 spawn attempt cursor를 분리하고, skip된 attempt가 다음
  spawn cell 선택을 고정하지 않게 한다.
- skip 횟수와 마지막 skip 원인을 DEV observer에서 확인할 수 있게 한다.

### 제외

- collider 반지름의 수치 조정은 [12.8](12.8-enemy-collider-density.md)에서
  별도로 처리한다.
- collision 계산의 frame budget·spatial index 중복 제거는
  [12.9](12.9-enemy-collision-performance.md)에서 처리한다.
- 별도 collision Worker/thread, OffscreenCanvas, 물리 엔진 도입
- 차량을 동적 rigid body로 바꾸는 작업

## 선택 설계

### 1. 적-적 push intent

`EnemyCollisionResolver`의 책임은 현재 위치를 고치는 것이 아니라, 한 frame의
적별 push intent를 계산하는 것으로 바꾼다.

1. frame 시작 시 생존 적의 위치를 기존 `EnemySpatialIndex`에 등록한다.
2. 적별로 인접 bucket에서 충돌 반경 안의 이웃을 bounded 조회한다.
3. 두 적의 거리가 최소 거리보다 작으면 pair normal과 penetration을 계산한다.
4. 양쪽 적에 같은 크기의 반대 방향 push를 누적한다.
5. 거리가 0이면 두 `navigationId`로 안정적인 normal을 만들고, 매 frame마다
   방향이 바뀌지 않게 한다.
6. push 강도와 이동 거리는 `dt`와 설정된 push 상한으로 제한한다.
7. `Enemy`는 path/local/engaged 이동 의도에 push intent를 합산한 뒤 기존 terrain
   safe movement로 적용한다.

따라서 spawn 직후 겹친 군집은 앞 적이 먼저 움직이고 그 힘이 다음 적에 전달되는
연속적인 chain push가 된다. 기존처럼 ring 후보를 탐색해 위치를 한 번에 옮기지
않는다. 정상 이동 중의 작은 접촉도 같은 경로를 사용하므로 steady state에서는
최소 거리 이상으로 수렴하고, spawn 직후의 짧은 transient overlap만 허용한다.

차량은 게임 상태를 소유하는 kinematic obstacle로 유지한다. 차량 내부로 적이
들어가는 것을 막는 기존 terrain-safe contact guard는 남기되, 적-적 군집을
펼치기 위한 강제 위치 변경으로 사용하지 않는다. 차량 push까지 intent 기반으로
바꾸는 것은 별도 증거가 있을 때 확장한다.

### 2. spawn admission

현재 `WaveManager.spawnEnemy()`는 spawn cell 중심에 즉시 적을 추가한다. 이를
다음 흐름으로 바꾼다.

1. 다음 spawn cell의 world point와 적 반지름이 terrain-safe인지 확인한다.
2. 주변 적을 spatial index에서 조회한다.
3. 겹침이 없으면 즉시 생성한다.
4. 겹침이 있으면 bounded한 push probe 방향을 확인한다. 적이 빠져나갈 수 있는
   terrain-safe 후보와 적 군집의 빈 공간이 하나라도 있으면 생성한다.
5. 모든 후보가 막혔거나 허용한 군집 밀도·이웃 수를 넘으면 생성하지 않고
   `spawnSkipped`를 증가시킨다.

spawn admission은 생성된 적을 다른 위치로 옮기지 않는다. 허용된 경우에도
원래 spawn point에서 시작해 다음 simulation update부터 push intent를 받는다.
포화 판정은 `maxSpawnPushNeighbors`, `spawnPushProbeDistance`처럼 데이터로
조정 가능한 최소 정책만 추가하고, 복잡한 전역 packing solver는 만들지 않는다.

실제 생성 수(`spawnedEnemiesCount`)는 성공한 적만 증가시킨다. 별도의
`spawnAttemptCursor`는 성공·skip 모두 증가시켜 특정 spawn cell에서 영원히
막히지 않게 한다. `lastSpawnBatchSize`는 실제 생성 수만 기록하고,
`spawnSkippedCount`와 `lastSpawnSkipReason`을 별도 observer 값으로 둔다.

### 3. Game update 순서

- spawn admission이 현재 적 집합과 index를 사용한다.
- coordinator가 만든 frame neighbor snapshot을 collision resolver가 재사용한다.
- `EnemyCollisionResolver.separate()`의 pre-update/post-update 호출을 제거한다.
- 적 update에는 `collisionPush` 또는 동등한 immutable intent만 전달한다.
- 적 update 후에는 vehicle contact guard와 death 수거만 수행한다.
- enemy-enemy 위치를 다시 전체 pass로 강제 보정하지 않는다.

## 자동 테스트

- 두 적이 겹치면 resolver가 양쪽에 반대 방향 intent를 반환한다.
- intent 계산만으로는 적의 `x/y`가 변경되지 않는다.
- exact-overlap 적 3~4마리가 여러 `dt`에 걸쳐 분리되고, 한 frame의 이동량이
  speed와 push 상한을 넘지 않는다.
- 앞 적이 벽에 닿은 chain에서도 뒤 적이 벽 안으로 밀리지 않는다.
- 작은 spawn 군집은 생성 후 여러 update에서 자연스럽게 펼쳐진다.
- 포화된 spawn cell은 새 적을 추가하지 않고 skip 횟수를 증가시킨다.
- spawn skip 뒤 다음 spawn cell로 cursor가 진행한다.
- 성공한 spawn만 `spawnedEnemiesCount`와 wave active set에 들어간다.
- 기존 contact damage, death/reward, wave count가 spawn skip으로 잘못 증가하지
  않는다.

## Runtime QA

필수 fixture:

- URL: `?test=1&scenario=enemy-collision-spawn`
- map: `aurelia/landing-zone`
- vehicle armor: `100`
- game over: disabled
- spawn: 작은 겹침 군집과 포화된 좁은 spawn 후보를 재현하도록 고정

기대 시간은 1분이고 절대 최대는 4분이다. 다음 순서로 한 번 실행한다.

- 0:00~0:15: canonical map, armor 100, fixture와 observer 초기화
- 0:15~0:35: spawn 직후 겹침이 한 frame teleport가 아니라 여러 update의
  push chain으로 해소되는지 확인
- 0:35~0:50: 벽 인접 군집에서 terrainUnsafe와 지속 stuck 여부 확인
- 0:50~1:00: 포화 spawn attempt의 count 불변·skip metric·console 확인
- 제품 동작 현상이 확인되면 최소 증거만 기록하고 즉시 `FAIL`로 종료한다.

통과 기준:

- spawn 군집의 적 위치가 resolver의 강제 ring 배치로 바뀌지 않는다.
- spawn 직후 허용된 transient overlap은 push chain으로 settle window 안에
  해소되고, 정상 이동 중 지속적인 overlap이 없다.
- 한 frame의 적 위치 변화가 speed·push 상한으로 설명 가능하다.
- terrainUnsafe, 벽 관통, 영구 stuck이 없다.
- 포화 상태에서는 live enemy가 추가되지 않고 `spawnSkippedCount`가 증가한다.
- armor 100으로 인해 전투 사망이 관측을 가리지 않는다.
- console error와 runtime exception이 없다.

## 완료 기준

- enemy-enemy collision path에서 직접적인 `x/y` depenetration이 제거된다.
- spawn overlap은 연속 push로 처리되고, 포화 상태의 spawn은 skip된다.
- spawn 성공·skip 통계가 observer와 wave semantics에 일관되게 반영된다.
- 단위 테스트, build, diff check와 필수 runtime QA가 통과한다.
