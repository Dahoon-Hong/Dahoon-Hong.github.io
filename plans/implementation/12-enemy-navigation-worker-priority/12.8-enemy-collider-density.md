# 12.8 적 collider 밀도 조정

상태: 구현 완료 (자동 검증 2026-09-14, runtime QA 대기)
상위 plan: [12. 적 시야 우선 추적 및 A* Web Worker 분리](12-enemy-navigation-worker-priority.md)
선행 subplan: [12.7 적 자연스러운 밀어내기와 spawn admission](12.7-enemy-natural-push-and-spawn-admission.md)

## 목적

현재 적 반지름은 standard 12px, tanker 18px이다. 이 값은 현재 코드에서
적-적 충돌, terrain footprint, pathfinding radius, 차량 contact 판정과
health bar 폭에 함께 사용된다. 값이 커서 군집이 지나치게 넓게 벌어지고 좁은
공간에 적이 빽빽하게 자리 잡지 못한다.

기존 `radius` 데이터 계약을 재사용해 collider footprint를 단계적으로 줄인다.
새로운 물리 타입이나 별도 collider 라이브러리를 도입하지 않고, 모든 경로·지형
검증이 같은 반지름을 사용하도록 유지한다.

## 요구사항 및 범위

### 포함

- `src/data/enemies.json`의 standard/tanker radius를 조정한다.
- 1차 후보값은 다음으로 고정해 비교한다.

| type | 기존 radius | 1차 후보 | 감소율 | 동일 타입 최소 거리(여유 제외) |
| --- | ---: | ---: | ---: | ---: |
| standard | 12 | 10 | 약 16.7% | 20px |
| tanker | 18 | 15 | 약 16.7% | 30px |

- `MapDefinitionLoader`의 spawn reachability와 `TerrainPathfinder`가 새 radius를
  사용하도록 검증한다.
- `EnemyCollisionResolver`, local steering, vehicle contact가 같은 radius를
  사용하도록 회귀 테스트한다.
- sprite 원본 픽셀 크기와 렌더링 scale은 변경하지 않는다.
- health bar가 논리 radius에 연결된 현재 계약 때문에 폭·offset이 함께 줄어드는
  영향은 runtime에서 확인하고, bar만 별도 visual radius로 분리하는 것은 이
  subplan의 범위에서 제외한다.

### 제외

- 적 타입별 HP, speed, contact damage, reward, spawn weight/interval/batch 변경
- map terrain row, spawn cell, tank collision 변경
- sprite 이미지 재생성·교체
- `collisionRadius`와 `visualRadius`를 새로 분리하는 구조 개편

## 선택 설계

### 1. 기존 radius 계약 유지

`EnemyDefinition.radius`와 `Enemy.radius`를 collider·terrain·pathfinding의
단일 기준으로 유지한다. 따라서 다음 호출은 모두 같은 새 값을 받는다.

- `TerrainGrid.isOpenForRadius()`와 `getSafeRadiusProgress()`
- `TerrainPathfinder.findPath()`와 `isPathValid()`
- enemy-enemy push의 최소 거리
- vehicle contact guard
- engagement slot gap와 local steering probe

이렇게 하면 작은 collider만 바꾸고 pathfinder가 이전 큰 footprint를 사용하는
불일치가 생기지 않는다. 시각적 sprite는 그대로 두며, health bar가 함께
축소되는 현재 구현의 부수 효과는 acceptance에서 확인한다.

### 2. 수치 조정 절차

1. 10/15 후보로 자동 검증을 실행한다.
2. 모든 생산 맵의 standard/tanker spawn path가 새 반지름으로 도달 가능한지
   loader 검증을 통과시킨다.
3. canonical test map에서 160 적 군집의 실제 최소 거리와 terrain safety를
   확인한다.
4. 화면에서 sprite overlap처럼 보이는지 확인한다. collider가 줄어도 sprite가
   과도하게 겹쳐 보이면 값 자체를 더 줄이지 않고 먼저 visual/collider 계약을
   재검토한다.

코드 계약 변경이 필요하지 않으면 `Enemy.ts`, `Game.ts`는 데이터 변경만으로
유지한다. 테스트가 이전 수치를 직접 기대하는 경우에만 해당 fixture를 새
radius 기준으로 갱신한다.

## 자동 테스트

- production enemy data가 standard 10, tanker 15를 로드한다.
- 새 radius 기준으로 모든 map의 enemy spawn-to-tank reachability가 통과한다.
- standard-standard, standard-tanker, tanker-tanker pair의 최소 거리가 각각
  합산 radius보다 작아지지 않는다.
- 기존 radius 기반 terrain collision과 corner clearance 회귀가 유지된다.
- 적 sprite asset ID와 이미지 크기 계약은 변경되지 않는다.
- contact damage, death/reward, wave spawn semantics가 수치 변경으로 깨지지
  않는다.

## Runtime QA

필수 fixture:

- URL: `?test=1&scenario=enemy-navigation-worker&worker=on`
- map: `aurelia/landing-zone`
- vehicle armor: `100`
- game over: disabled
- fixed load: 160 standard enemies

기대 시간은 1분이고 절대 최대는 4분이다. 기존 radius 기준과 새 radius 기준을
같은 실행에서 반복하지 않고, fixture snapshot과 새 값의 observer를 한 번
확인한다.

- 0:00~0:15: map, armor 100, radius와 enemy count 기록
- 0:15~0:40: 군집이 target 방향으로 이동하는 동안 collider 밀도와 sprite 표시 확인
- 0:40~0:55: 벽·좁은 길·차량 주변에서 terrainUnsafe와 stuck 확인
- 0:55~1:00: 최소 거리, contact, console과 최종 상태 기록
- 제품 동작 현상이 확인되면 즉시 `FAIL`로 종료한다.

통과 기준:

- standard/tanker가 기존보다 가까운 최소 거리로 안정적으로 자리 잡는다.
- 적 sprite가 서로 완전히 겹쳐 보이거나 terrain을 관통하지 않는다.
- 새 radius로도 모든 적이 벽을 통과하지 않고 path를 유지한다.
- `terrainUnsafe=0`, 지속 `stuck=0`, GAME_OVER 없음
- armor 100 fixture가 사망 때문에 density 관측을 가리지 않는다.
- console error와 runtime exception이 없다.

## 완료 기준

- 후보 radius가 data·pathfinding·collision 전 영역에 일관되게 적용된다.
- 적 군집 밀도가 개선되고 terrain/path reachability가 회귀하지 않는다.
- HP/speed/damage/wave 밸런스는 변경하지 않는다.
- 단위 테스트, build, diff check와 필수 runtime QA가 통과한다.
