# 26.1 지형 데이터 계약과 TerrainGrid

## 목표

36px cell 기반 지형 데이터를 로드하고, 탱크·적·탄환이 공유하는 순수 지형 질의 계층을 만든다. 이 단계에서는 실제 충돌 행동을 바꾸지 않고 이후 sub plan이 사용할 데이터와 API를 확정한다.

## 선행 조건

- [Plan 26 설계 명세](../../docs/superpowers/specs/2026-09-07-plan-26-terrain-world-map-design.md)
- 현재 `maps.json`, `Camera`, `Game.renderMap()` 흐름 확인

## 구현 범위

### Map 데이터 계약

- 모든 playable map에 `${planetId}/${regionId}` 형식의 안정적인 `mapId`를 부여한다.
- `maps.json` 최상위에 `open`, `hill` terrain type과 대상별 `blocks` 설정을 둔다.
- terrain map은 `cellSize`, `columns`, `rows`, `legend`, 문자 row를 가진다.
- map별 탱크 시작 cell과 적 스폰 cell 목록을 추가한다.
- 월드 크기는 `columns * cellSize`, `rows * cellSize`로 계산한다.
- 26.8 전환 전 기존 장식 전용 map은 명시적인 all-open fallback으로 읽되, 최종 단계에서 fallback 의존을 제거한다.

### Loader와 validation

- raw JSON을 runtime 타입으로 변환하는 `MapDefinitionLoader` 또는 동등한 작은 loader를 추가한다.
- 다음 오류를 시작 시 명확히 보고한다.
  - 중복 `mapId`
  - 36이 아닌 cell size
  - row 개수 또는 길이 불일치
  - legend에 없거나 terrain type에 없는 symbol
  - 누락된 `tankStartCell` 또는 빈 enemy spawn 목록
  - 범위 밖이거나 대상에게 차단된 시작/스폰 cell
  - 잘못된 asset ID 참조
- 로더 밖의 코드가 raw `maps.json` 타입 추론에 의존하지 않게 한다.

### TerrainGrid

- 새 `TerrainGrid`는 map 하나의 immutable terrain 상태를 가진다.
- 최소 API를 제공한다.
  - world point ↔ terrain cell 변환
  - cell bounds와 world bounds 조회
  - `isBlocked(cell, 'tank' | 'enemy' | 'projectile')`
  - AABB 또는 radius footprint와 겹치는 cell 조회
  - 8방향 neighbor 조회
  - 선분이 통과하는 cell 순회와 첫 차단 cell 조회
- 좌표가 world 밖이면 모든 collision target에 대해 차단으로 취급한다.
- art asset과 Canvas context는 참조하지 않는다.

### Game 연결 준비

- 현재 region 조회를 `mapId` 기반 조회로 바꿀 수 있는 진입점을 만든다.
- Camera가 선택된 map의 world size를 받을 수 있게 생성/재설정 경계를 정리한다.
- `Game.renderMap()`은 loader가 반환한 typed map만 사용한다.
- 초기 pickup 생성이 탱크 시작점 주변의 `tank` 통과 가능 cell만 고를 수 있도록 helper를 제공한다.

### 테스트 기반

- A*, raycast, 저장소처럼 비결정적 버그 위험이 큰 후속 로직을 검증할 수 있도록 Vitest를 dev dependency로 추가한다.
- `npm test`를 `vitest run`으로 등록한다.
- TerrainGrid 좌표 경계, 차단 조합, 잘못된 row/legend, world 밖 판정을 작은 unit test로 남긴다.

## 완료 기준

- map ID로 typed map과 TerrainGrid를 얻을 수 있다.
- world bounds가 terrain grid 크기에서 계산된다.
- `open`과 `hill`의 세 대상 차단 조합이 데이터만으로 결정된다.
- 잘못된 map 데이터가 조용히 fallback되지 않고 validation error를 낸다.
- 기존 네 지역은 all-open 호환 상태로 계속 실행된다.
- `npm test`와 `npm run build`가 성공한다.

## 수동 QA

1. 기존 첫 지역을 실행해 map과 Camera 크기가 기존과 동일한 체감으로 표시되는지 확인한다.
2. map asset 누락 fallback이 terrain 판정을 바꾸지 않는지 확인한다.
3. 개발 중 잘못된 row 길이를 넣었을 때 오류 위치가 식별 가능한지 확인한 뒤 원복한다.
