# 25.1 월드 확장과 카메라

## 목표

현재 gameplay viewport에 고정된 전투를 상하좌우로 확장된 월드에서 실행하고, 탱크 이동에 맞춰 카메라가 스크롤하도록 한다.

## 선행 조건

- 현재 Game loop, Vehicle 이동, WaveManager spawn, HUD screen 좌표 흐름 확인
- [Plan 25 설계 명세](../../docs/superpowers/specs/2026-09-06-plan-25-gameplay-expansion-design.md)

## 구현 범위

### 월드 좌표와 Camera

- `Camera` value object 또는 작은 클래스를 추가한다.
- world bounds, viewport size, camera position, follow target, clamp를 관리한다.
- `worldToScreen`과 `screenToWorld` 변환을 제공한다.
- 탱크를 부드럽게 추적하되 카메라가 월드 경계를 벗어나지 않게 한다.
- HUD panel/top bar는 camera 변환 밖에 둔다.

### Game loop와 entity 좌표

- Vehicle, Enemy, ResourcePickup, Projectile, VisualEffect는 월드 좌표를 유지한다.
- `Game.update()`의 이동 bounds와 `WaveManager`의 spawn bounds를 확장 월드 기준으로 바꾼다.
- 월드 내 pickup 초기 위치와 enemy spawn 위치가 화면 밖에서도 유효하도록 한다.
- 렌더링 시 gameplay clip 안에서 camera offset을 적용하고, HUD는 기존 논리 좌표로 렌더링한다.
- 적-grid 접촉 판정은 camera가 아닌 월드 좌표로 수행한다.

### 맵 렌더링

- 현재 region map background를 확장 월드에 반복 배치한다.
- tile, prop, spawn-edge도 world bounds에 맞춰 반복/배치한다.
- map asset의 원본 크기나 region 데이터의 decorativeOnly 계약은 변경하지 않는다.
- 새 대형 map 원화와 장애물 collision은 추가하지 않는다.

## 변경 대상

- `src/core/Game.ts`
- `src/core/WaveManager.ts`
- 새 `src/core/Camera.ts` 또는 동등한 최소 파일
- `src/entities/Vehicle.ts`
- `src/entities/Enemy.ts`, `ResourcePickup.ts`, `Projectile.ts`의 render 좌표 연결부
- `src/data/maps.json`이 필요할 경우 world size metadata만 추가

## 완료 기준

- 탱크가 현재 화면보다 넓은 월드의 상하좌우로 이동한다.
- 카메라가 탱크를 따라가고 월드 경계에서 멈춘다.
- 탱크가 화면 가장자리에서 잘리지 않는다.
- 적, 픽업, 탄환, 효과가 camera 이동에 맞춰 함께 이동한다.
- HUD와 panel click 좌표가 camera 이동의 영향을 받지 않는다.
- `npm run build` 성공.

## 수동 QA

1. 시작 위치에서 맵 장식과 탱크가 정상 표시되는지 확인한다.
2. W/A/S/D와 방향키로 각 방향 끝까지 이동한다.
3. 카메라가 부드럽게 이동하고 월드 경계 밖으로 표시되지 않는지 확인한다.
4. 이동 중 적·픽업·탄환의 상대 위치가 유지되는지 확인한다.
5. PAUSED와 terminal overlay가 camera 이동 후에도 HUD 위치에 고정되는지 확인한다.
