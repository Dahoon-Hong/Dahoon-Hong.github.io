# 콘텐츠 추가 가이드

이 디렉터리는 사람과 에이전트가 같은 절차로 게임 콘텐츠를 추가하기 위한 현재 구현 기준 가이드다.

## 어떤 가이드를 읽어야 하는가

| 요청에 포함된 내용 | 읽을 가이드 |
| --- | --- |
| 무기, weapon, 전투 모듈, 포탑, 발사 방식 | [무기 모듈](weapon-modules.md) |
| 업그레이드, 강화, 연구 노드, 스탯 증가 | [업그레이드](upgrades.md) |
| 탱크, tank, 차체, 모듈 격자 | [탱크](tanks.md) |
| 맵, map, 지역, 스테이지, 지형 | [맵](maps.md) |
| 적, enemy, 몹, 웨이브 유닛 | [적](enemies.md) |

사용자가 “이런 컨셉으로 탱크 추가해줘”처럼 가이드 이름을 말하지 않아도 요청 대상에 맞는 가이드를 적용한다. 한 요청이 여러 콘텐츠를 건드리면 관련 가이드를 모두 읽는다.

## 공통 작업 순서

1. 요청에서 컨셉과 필수 입력을 추출한다.
2. 해당 가이드의 `필요한 정보`와 비교한다.
3. 결과를 크게 바꾸는 정보가 없으면 구현 전에 사용자에게 확인한다.
4. 기존 콘텐츠 중 가장 가까운 예제를 찾는다.
5. 데이터만으로 가능한 확장인지, 런타임 코드가 필요한 확장인지 구분한다.
6. 가이드의 파일 표에 따라 최소 범위만 수정한다.
7. 자동 검증 후 실제 플레이로 완료 조건을 확인한다.

## 구현 계약의 우선순위

1. 현재 로더와 타입
2. 현재 테스트와 QA 스크립트
3. 이 디렉터리의 승인된 가이드
4. 기존 계획 및 과거 설계 문서

가이드와 현재 구현이 다르면 구현을 근거로 작업하고, 같은 작업에서 가이드도 갱신해야 하는지 사용자에게 알린다. 계획 문서를 현재 데이터 계약의 근거로 사용하지 않는다.

## 공통 검증

변경 범위에 맞는 검증을 실행한다.

```text
npm test
npm run qa:art
npm run qa:audio   # 오디오를 변경한 경우
npm run build
npm run dev
```

최종 통합 검증이 필요하면 `npm run qa:release`를 사용한다. 개발 서버에서는 메뉴 진입만 보지 말고 새 콘텐츠가 실제로 생성되고 표시되며 플레이 규칙대로 동작하는지 확인한다.

## 문서 변경 규칙

이 가이드는 승인된 규칙만 보관한다. 미확정 컨셉, 향후 아이디어, 작업 중 메모는 여기에 확정 사항처럼 추가하지 않는다. 자세한 규칙은 상위 [docs 작업 지침](../agents.md)을 따른다.
