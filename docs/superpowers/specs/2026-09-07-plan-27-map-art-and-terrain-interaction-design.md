# Plan 27: 맵 이미지·지형 경계·탱크 상호작용 설계

작성일: 2026-09-07

상태: 계획 문서화 완료, 구현 전

구현 순서와 단계별 완료 기준: [6번 맵 아트·지형 구현 계획](../../../plans/implementation/6-map-art-terrain/6-map-art-terrain.md)

## 목표와 사용자 의도

- 벽과 언덕은 완성 맵 이미지 안에서 표현한다. 별도 장애물 게임 오브젝트나 반복 바위 스프라이트를 화면에 얹지 않는다.
- 이미지에서 보이는 통과 불가 지형과 실제 이동 불가 영역이 일치해야 한다.
- 탱크는 이동하거나 회전하는 도중에도 차체가 벽을 관통하지 않아야 한다.
- 벽을 따라 이동하거나 코너를 돌 때 조기 정지, 걸림, 떨림을 줄인다.
- 변경은 기존 Canvas 렌더링과 TerrainGrid를 중심으로 작게 유지하고, 실제 조정이 필요한 값은 JSON으로 관리한다.

이 문서의 충돌 마스크는 이미지와 함께 제작하는 **숨겨진 지형 윤곽 데이터**를 뜻한다. 런타임 표현은 정적 다각형 JSON이며, 별도 장애물 엔티티나 픽셀 색상 판독을 뜻하지 않는다.

## 현재 구조와 문제

2026-09-07 코드와 원본 이미지 조사 기준이다. 구현 시작 시 관련 파일의 최신 변경을 다시 확인한다.

- `Game.renderMap()`은 이미 벽과 폐허가 그려진 배경을 반복 렌더링한다. `repeat.background: false`를 렌더링에 반영하지 않는다.
- `Game.renderTerrain()`은 별도 36px terrain row의 hill마다 바위 이미지를 그린다. 중심·가장자리·모서리 asset도 동일한 원본을 참조해 연속 지형보다 작은 바위의 반복으로 보인다.
- 현재 배경의 논리 크기는 940×720, 월드는 2880×2160이다. 배경 구조물과 terrain row가 서로 다른 배치 기준을 가진다.
- `Vehicle.getTerrainFootprint()`는 회전하지 않는 사각형을 반환하지만 실제 차체는 회전한다. 현재 프레임을 포함한 120×120 사각형은 45도 회전 시 축 방향 폭이 약 170px이 되어 기존 판정 밖으로 보일 수 있다.
- `Vehicle.update()`는 방향을 즉시 바꾸고 X축 전체 이동 후 Y축 전체 이동을 수행한다. 충돌한 이동 step 전체를 취소하므로 접촉점보다 일찍 멈추며 축 순서에 따른 차이가 생긴다.
- 시작 위치 검증은 중심 cell 위주다. 적 길찾기도 cell 중심의 통과 여부만으로는 비정형 지형 사이 이동 구간의 안전성을 보장할 수 없다.

## 접근 방식 선택

| 방식 | 판단 |
| --- | --- |
| 완성 이미지 + 정적 다각형 윤곽 | 채택. 비정형 벽과 언덕의 경계를 따라가며 접촉 방향을 계산할 수 있다. 기존 grid를 재사용한다. |
| 완성 이미지 + 기존 36px 차단 cell | 변경은 작지만 거친 계단 경계가 남고 이미지 표현이 격자에 제한된다. |
| 고해상도 픽셀 마스크를 직접 판정 | 윤곽을 표현하기 쉽지만 해상도별 처리와 접촉 방향 계산이 추가된다. 전체 A* 격자를 세밀하게 바꾸는 방식도 피한다. |

## 맵 데이터와 아트 제작 계약

### 공통 좌표

- 기존 `world.cellSize`, `columns`, `rows`와 map ID를 유지한다. 현재 다섯 맵의 월드 크기는 2880×2160이다.
- 완성 이미지의 논리 표시 범위는 월드 전체이며 원점은 `(0, 0)`이다. 최종 런타임 PNG는 이 크기에 맞춰 정규화한다.
- 지형 윤곽의 모든 꼭짓점은 같은 월드 좌표를 사용한다. 화면 크기나 카메라 위치로 좌표를 저장하지 않는다.
- 기존 `assets.background` 참조를 완성 이미지에 재사용하고, 전환한 맵은 한 번만 그린다.

### 지형 윤곽

- `terrain.regions`에 영역 ID, terrain type, 꼭짓점 목록을 저장한다. terrain type은 기존 대상별 `blocks` 설정을 참조한다.
- 각 영역은 면적이 있는 단순 볼록 다각형이다. 복잡하거나 오목한 지형은 몇 개의 볼록 영역으로 나눠 작성한다.
- 같은 고형 지형을 나눈 내부 접합선은 이동을 막는 외부 벽으로 취급하지 않는다. 접촉 처리와 QA에 접합부 통과를 포함한다.
- 꼭짓점 유한값, 월드 범위, 최소 점 수, 중복 점, 면적, 자기 교차, 볼록성, type 참조를 검증한다.
- 미전환 맵의 terrain row는 마이그레이션 동안만 지원한다. 한 맵에서 rows와 regions를 동시에 판정 원본으로 두지 않으며, 전체 전환 후 구형 런타임 경로를 정리한다.

### 이미지와 경계를 함께 만드는 순서

1. 길, 광장, 벽, 언덕, 시작점과 스폰 위치의 공통 레이아웃 및 차단 윤곽을 먼저 정한다.
2. 해당 윤곽 가이드를 기준으로 완성 맵 이미지를 생성하거나 편집한다. 벽을 별도 스프라이트로 분리해 배치하지 않는다.
3. 이미지의 지면상 고형 지형 경계와 JSON 윤곽을 겹쳐 확인하고, 어긋난 이미지 또는 윤곽을 함께 수정한다.
4. 최종 이미지를 월드 크기로 정규화하고 asset manifest와 생성·편집 이력을 기록한다.
5. 대표 직선 벽, 비정형 언덕, 안쪽·바깥쪽 코너의 검증 이미지를 남긴다.

그림자, 빛 번짐, 얕은 균열과 작은 바닥 장식은 차단하지 않는다. 큰 벽이나 언덕처럼 보이는 고형 구조를 열린 바닥의 장식으로 남기지 않는다. 기준은 그림자의 외곽이 아닌 지면에서 읽히는 고형 지형 경계다. 대표 경계의 시각 오차 목표는 월드 좌표 2px 이내로 둔다.

## 공통 지형 판정

- `TerrainGrid`를 탱크·적·탄환·시야·스폰이 공유하는 진입점으로 유지한다. 호출부가 raw JSON이나 이미지를 직접 해석하지 않는다.
- 36px cell마다 겹치는 지형 영역을 찾아 주변 후보를 좁힌다. cell 점유는 파생 정보이며 최종 접촉 경계가 아니다.
- 점, 차체 외곽, 적 반지름, 이동 구간, 선분 raycast의 정확한 판정은 같은 다각형 데이터를 사용한다.
- 원형 적의 경로는 waypoint 중심뿐 아니라 waypoint 사이의 반지름을 포함한 이동 구간도 검사한다. 경로 압축 구간과 실제 적 이동에도 동일한 경계를 적용한다.
- direct와 arc는 기존처럼 `projectile` 차단 규칙을 공유한다. 첫 접촉 위치에 탄환 충돌 효과를 표시하고 자동 조준도 같은 raycast를 사용한다.
- 탱크 시작 위치는 초기 차체 크기와 각도로, 적 스폰은 실제 반지름으로 검증한다. 초기 픽업은 탱크가 접근 가능한 열린 공간에 배치한다.
- 이미지 로드 실패가 열린 지형으로 바뀌는 원인이 되어서는 안 된다. 실패 시 실제 경계 기반의 단순 지형 표시로 판정 위치를 드러낸다. 잘못된 윤곽 데이터는 명확한 로딩 오류로 처리한다.

## 탱크 이동과 회전

### 충돌 외곽과 관통 방지

- 현재 차체 프레임까지 포함한 로컬 외곽을 기준으로 회전 사각형을 계산한다. 그림자, 포신 효과와 장식까지 이동 충돌 범위에 포함하지 않는다.
- 고정 3×3 수치를 새 충돌 함수에 하드코딩하지 않고 현재 탱크 정의의 크기를 사용한다. 새로운 탱크 확장 기능은 추가하지 않는다.
- 후보 끝점만 검사하지 않고 이동 구간의 최초 접촉을 구한다. 얇은 지형과 큰 frame delta에서도 차체가 건너뛰지 않아야 한다.
- 회전도 시작각과 끝각 사이의 차체 외곽을 검사한다. 양 끝 자세가 유효하더라도 중간 회전이 벽과 겹치면 마지막 안전각까지만 허용한다.
- 월드 경계도 같은 자세 검사에 포함한다. 이동 후 축 정렬 clamp로 유효한 자세를 다시 벽 안으로 밀어 넣지 않는다.

### 벽면과 코너

- 입력 이동량에서 최초 충돌 지점까지 진행하고, 남은 이동량 중 벽을 향하는 성분을 제거한다.
- 남은 접선 이동도 다시 검사해 두 벽을 동시에 만나는 안쪽 코너에서 안정적으로 멈춘다.
- 고정 X→Y 처리 순서의 영향을 제거한다. 좌우가 대칭인 코너는 대칭적인 이동 결과를 가져야 한다.
- 작은 접촉 여유와 제한된 반복 횟수를 사용하고, 반복 한도에 도달하면 마지막 안전 위치에 멈춘다. 남은 이동을 검사 없이 적용하지 않는다.
- 접선 이동을 무조건 원래 속도로 재정규화하지 않아 코너에서 속도가 증가하지 않게 한다.

### 부드러운 방향 정렬

- 실제 이동이 있으면 확정된 이동 방향을 목표로 삼아 회전 속도 제한을 적용한다.
- 회전이 막혀도 가능한 벽면 이동을 취소하지 않는다. 현재 안전각으로 이동한 뒤 여유가 생기면 방향을 맞춘다.
- 실제 이동이 없고 입력이 있으면 안전한 제자리 회전을 시도할 수 있다. 이동해야 회전하고 회전해야 이동하는 순환 정체를 방지한다.
- 입력이 없으면 마지막 방향을 유지한다. 벽 안으로 밀어내기, 순간이동, 입력과 무관한 자동 코너 우회는 추가하지 않는다.
- 궤도 애니메이션은 확정된 실제 이동량을 사용하고, 모듈 배치·사격 각도·입력 좌표는 최종 차체 각도를 공유한다.
- 회전 속도, 접촉 여유, 충돌 반복 한도 등 조정 값은 기존 `src/data/vehicle-motion.json`에 필요한 항목만 추가한다.

## 검증과 성공 기준

### 자동 검증

- 잘못된 다각형, 범위 밖 좌표, 중복 map/region ID 및 누락 asset 참조를 검출한다.
- 알려진 벽 좌표와 차체 크기로 예상 접촉 위치를 검증한다. 구현의 유효성 함수를 다시 호출하는 검사만으로 관통 방지를 증명하지 않는다.
- 직선·대각선 접근, 얇은 벽, 고속·큰 frame delta, 회전 중간 접촉과 월드 네 변을 포함한다.
- 볼록 지형을 나눈 접합부, 좌우 대칭 코너, 두 벽 동시 접촉, 회전과 이동이 서로 막는 입구를 재현한다.
- 기본 차체와 다른 직사각형 크기의 테스트 정의로 치수 하드코딩을 검출한다.
- 시간 기준으로 동일한 입력을 30/60/120fps 간격에 재생한다. 모두 비관통 조건을 만족하며 지정된 코너 경로를 완료해야 한다. 자유 이동·직선 벽면 이동의 최종 위치 차이는 월드 좌표 2px 이내를 목표로 한다.
- 적 반지름을 포함한 경로 구간, 모든 스폰의 도달 가능성, direct/arc 최초 접촉과 LOS를 검증한다.

### 시각 및 실제 플레이 검증

- 개발 실행에서 각 맵의 이미지 위에 실제 다각형, 회전한 차체 외곽과 접촉 지점을 표시한다. 일반 플레이는 기본 off다.
- 이미지 크기·참조·좌표 검사와 시각적 일치는 별도로 검증한다. `qa:art` 성공만으로 벽 경계의 일치를 판정하지 않는다.
- `terrain-test`에서 직선 벽, 비정형 언덕, 안쪽·바깥쪽 코너, 협로, 교차로, 막다른 길과 후진을 확인한다.
- 테스트 맵 통과 후 실제 네 지역의 주요 통로, 회전 공간, 적 스폰, 픽업과 엄폐를 확인한다.
- `npm test`, `npm run qa:art`, `npm run build`와 `npm run dev` 또는 이미 실행 중인 개발 서버로 검증한다.
- 최대 웨이브의 적 이동과 카메라 스크롤에서 성능을 확인한다. 문제가 재현되기 전에는 worker, navmesh나 별도 경로 캐시를 추가하지 않는다.
- 검증 실행 결과, 대표 경계 화면, 코너 재현 결과와 실제 수행한 플레이 범위는 구현 완료 시 `docs/plan-27-verification.md`에 기록한다.

## 범위 제외

- 별도 장애물 엔티티, 파괴 가능하거나 움직이는 지형
- 높이·경사에 따른 물리, 점프, 무기별 지형 관통 예외
- 외부 물리 엔진, navmesh, 전용 맵 편집기
- 런타임 이미지 색상 분석과 전체 A* 격자의 고해상도 전환
- 캠페인, 적 수치, 웨이브 구성, 생산·수집 규칙 변경
- 요청 범위 밖의 UI, 저장 시스템, 탱크 확장 기능

일시정지 중에는 기존대로 모듈 설치·업그레이드를 허용하고, 이동·회전·전투·자동 생산·자원 수집은 진행하지 않는다.
