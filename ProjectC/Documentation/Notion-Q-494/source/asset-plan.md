# Project C 자산·표현 계획 — Q-494 반영

- 근거: [확정 기획](planning.md)의 GR-450~454와 기존 시각/음향·예산 요구.
- MVP 그래픽은 무료 자산+보정을 기반으로 하고 구매 예산은 음악·효과음 완성도에 우선 배분합니다. 총 에셋 구매 상한은5만원입니다.
- 첫 검증 버전은 기존 GR-444대로 임시 그래픽·기본 UI를 사용합니다. 이 계획은 정식 자산 준비의 기준이며 실제 조사·구매·가공 결과가 아닙니다.
- Q-480·481: Unity+C#에서3D 모델을 고정 카메라로 보여주고 픽셀 느낌을 적용합니다. 기본 지도·시설·유닛 경로를2D 스프라이트 자산 제작으로 확정하지 않습니다.

## 자산 선정 순서

1. 원본 출처·저작자·실제 라이선스/사용 조건과 AI 열람·수정·검증 가능 여부를 확인합니다. 이름이나 무료 표시만으로 권한을 추정하지 않습니다.
2. 지도·시설·유닛은 조건이 확인된 무료3D 모델 후보에서 고정 쿼터뷰·현대 산업/군사·중간 수준 픽셀 표현에 맞게 가공 가능한 소재를 선별합니다. UI·아이콘 등은 용도에 맞는 이미지 자산을 유지합니다.
3. 기능 식별을 위해 공통 색상·재질·크기·대표 장치·필요한 동작을 보정합니다. 실제 시설 점유와 충돌 판정은 기존 규칙을 사용합니다. 렌더링한 실제 화면에서 묘사 수준·약한 사용감·실루엣을 확인합니다.
4. 음악·효과음은 기존 재생 정책에 맞는 후보를 검토하고 남은 전체 예산 안에서 품질을 우선 비교합니다. 실제 조건·비용 검토 전 특정 구매를 확정하지 않습니다.
5. 가공한 자산은 실제 화면 크기·지도 줌·표시 배율에서 AI가 직접 열람/실행 결과를 확인할 수 있는 형태로 검증합니다.

## 영역별 기본 방침

| 영역 | 기본 경로 | 검증 기준 |
| --- | --- | --- |
| 시설·유닛·지형 그래픽 | 무료3D 모델 선별 후 공통 스타일 보정 | 종류/기능 식별, 고정 쿼터뷰, 대표 장치·픽셀 표현 묘사 수준 |
| UI·아이콘 | 무료 자산·기본 도형을 기존 남색/청록 방향에 맞춰 정리 | 필수 정보/조작 접근, 비색상 단서, 한/영·지원 배율 |
| 지도 픽셀 표현 | 픽셀 선명함을 우선한 줌 단계 검증 | 확대 단계별 경계·정렬·식별성, UI 배율과 독립 |
| 음악·효과음 | 구매 예산 우선 평가, 무료 적합 후보도 비교 | 차분한 산업/전자 분위기, 기존 재생 대상과 음량 설정 |

- 예산 우선순위는 각 영역의 확정 필수 요구를 삭제하는 근거가 아닙니다.
- 사용 조건·원본 형식 때문에 사람만 처리할 수 있는 후보는 선택하지 않습니다. 무료 후보와 유료 음향 후보 모두 같은 AI 처리 가능 기준을 적용합니다.
- 자산별 출처·조건·표기 의무·허용 가공 범위·원본/가공본·검증 상태를 관리합니다. 실제로 확인한 사실과 미확인 사항을 구분합니다.
- 음악·효과음 품질 우선은 웨이브 예고/전초 피격 경고음 추가를 뜻하지 않습니다. 실제 접안·출발, 선택한 생산 시설 가동음과 기존 음량 정책을 유지합니다.
- GR-485~489: 게임 장면은 픽셀 느낌, UI·글자는 선명하게 유지합니다. 직교 카메라·일정한 조명·절제된 그림자에서 대표 장치와 실루엣이 읽히는지 확인합니다.
- 모델의 형태·높이는 가림을 줄이도록 보정하고 선택 윤곽을 연결합니다. 실제 점유·충돌 범위와 지도 배치를 바꾸지 않습니다.
- 첫 작은 전체 흐름 검증판에서 대표 시설·지형에 새 표현을 적용해 검토합니다. 모든 최종 모델·효과를 먼저 완성하지 않습니다. 구체 효과 구현·픽셀 크기는 실제 화면 검증에서 정합니다.
- GR-484: 무료 자산과 보정만으로 필요한 표현을 충족하기 어려우면 해당 자산을 고르기 전에 사용자와 대안을 먼저 논의합니다. 부족한 항목·기존 후보·가공 제약·비용/작업 영향을 구체화하고 AI 신규 제작·그래픽 구매·음향 예산 재배분을 임의로 확정하지 않습니다.
- 실제 무료 모델 후보의 부족은 아직 확인하지 않았습니다.3D 표현 선택만으로 예산·묘사 수준·기능 식별 기준을 바꾸지 않습니다.

## 제작·인계 연결 — GR-490~494

- 조정이 필요하면 그림자·후처리·장식 효과의 비용부터 확인하며 기능 식별·게임 규칙을 유지합니다.
- BGM은 한 가지 차분한 산업·전자음악 분위기로 자연스럽게 반복합니다. 국면별 음악 전환이나 전투 반응형 음악을 새 필수 기능으로 넣지 않습니다.
- 자산은 원본·가공 방법·최종본과 출처·조건·검증 기록을 함께 관리합니다. 공개 Git 저장소 포함 여부는 실제 보관/재배포가 허용되는 범위로 처리합니다.
- 원본 보관 방식·가공 이력 구조 등 일반 관리 선택은 기존 원칙에서 AI가 도출합니다. 자산 부족·권한 제약으로 확정 방향을 충족하기 어려우면 구체 대안을 갖춰 사용자에게 질문합니다.
