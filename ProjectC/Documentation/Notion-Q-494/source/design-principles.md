- 가능한 조치는 현재 시설 상태와 기존 규칙에서 확인한 항목만 표시합니다. 공급망 최적해를 보장하는 자동 조언자·시설 자동 배치는 추가하지 않습니다.

## 첫 검증 계획으로 연결한 도출 설계

- DD-007: 전체 흐름에서 첫 실제 하역·생산·전초기지 중계·터렛 보급/교전·결정 수출 출발을 연결합니다. 최종 MVP 축소나 새 단축 모드가 아닙니다. 근거: GR-440.
- DD-008: 잘못된 상태/물자 보존 오류와 의도된 규칙의 난이도 문제를 분리합니다. 기능 오류를 숫자 조정으로 숨기지 않고 밸런스 문제는 수치·초기 배치부터 검토합니다. 근거: GR-441·442.
- DD-009: 플레이 체감 기록과 핵심 사건 시각·재고/자금 변동을 같은 실행에서 연결합니다. 내부 검증 자료로 사용하며 새 고급 통계 화면을 추가하지 않습니다. 근거: GR-443·439.
- DD-010: 임시 자산으로도 시설 종류·품목·구역·연결/문제·선택 상태를 구분하고 최종 아트 정교화는 전체 흐름 검증 뒤에 진행합니다. 기존 자산 방향·예산·UI 요구는 유지합니다. 근거: GR-444.
- 상세 계획: [first-validation.md](first-validation.md). 모두 원칙에서 도출한 설계이며 구현·검증 완료가 아닙니다.

## 플레이 판단·운영 부담에서 도출한 설계

- DD-011: 플레이 정보는 현재 병목과 다음 국면 준비에 우선순위를 둡니다. 전체 미래 웨이브 표를 필수 추가 UI로 만들지 않습니다. 기존 전체 지도·기한/시간·비용/결과 안내를 숨기거나 이미 알려진 기본 규칙을 불명확하게 만들지 않습니다. 근거: GR-445·436·437.
- DD-012: 장기 반복 대량 수송은 벨트 연결의 효과를, 초기 공급·변동 수요·현장 작업은 드론의 유연함을 검증합니다. 모든 수송 수단이 항상 대등해야 한다는 목표를 두지 않으며 기존 성능값을 바로 바꾸지 않습니다. 근거: GR-446.
- DD-013: 계획·점검에 수동 정지를 사용하는 플레이를 유효한 방식으로 평가하고 빠른 조작만으로 문제를 해결하도록 요구하지 않습니다. 메뉴·관리창 자동 정지는 추가하지 않고 게임 시간과 실제 조작/정지 시간을 구분해 관찰합니다. 근거: GR-447·369·411.
- DD-014: 같은 승리 목표에서 피해를 줄이는 투자와 일부 피해 후 복구 비용을 비교합니다. 무피해를 새 승리 조건·추가 필수 결과 통계로 만들지 않습니다. 전초기지 파괴와 수동 수리 규칙을 우회하지 않습니다. 근거: GR-448.
- DD-015: 수출이 안정된 정상 확장에서 자금이 남아도 원료 처리·수송·공간 때문에 증설 판단이 생기는지 확인합니다. 무계획 지출의 자금 부족까지 제거하거나 실제 결제/가격을 무시하지 않습니다. 근거: GR-449.

## 정식 자산·표현에서 도출한 설계

- DD-016: 자산 조사 전에 AI 처리 가능성과 실제 사용 조건을 확인하고, 통과한 무료 그래픽을 기능 식별·시점·크기·색상 기준으로 선별합니다. 보기 좋은 자산이라도 사람 전용 처리가 필요한 경로는 채택하지 않습니다. 근거: GR-451·454.
- DD-017: 무료 그래픽은 공통 팔레트·실루엣·대표 장치·기준 크기를 보정합니다. 실제 시설 점유/충돌과 식별용 외형을 분리하고 기존 묘사 수준을 유지합니다. 근거: GR-450·451·359.
- DD-018: 지도 줌은 픽셀 선명함을 만족하는 표시 단계에서 검증하고 필요하면 제한합니다. UI 배율과 별도로 다루며 정확한 줌 수치는 표현 검증으로 정합니다. 근거: GR-452.
- DD-019: 그래픽은 무료 기반으로 준비하고, 전체 구매 예산5만원 안에서 음악·효과음 품질을 먼저 평가합니다. 실제 구매 금액을 미리 배정하거나 모든 예산을 반드시 소진하지 않습니다. 근거: GR-451·453·361.
- DD-020: 음향 우선 투자는 기존에 정한 재생 대상·알림 정책의 품질 개선입니다. 새 경고음·음성·항시 기계음을 더해 범위를 넓히지 않습니다. 근거: GR-453·380~384.
- 상세 선별·제작 기준은 [asset-plan.md](asset-plan.md)를 따릅니다. 아직 자산 조사·구매·보정·음향 검증을 실행하지 않았습니다.

## 실행 환경·품질에서 도출한 설계

- DD-021: 개발/초기 검증 환경과 최종 배포/호환성 검증 환경을 별도로 기록합니다. 다른 환경의 성공만으로 Windows 호환성을 통과 처리하지 않습니다. 근거: GR-455.
- DD-022: 초기 브라우저판은 핵심 흐름과 조작 체감의 중간 증거로 사용합니다. 최종 Windows 실행·오프라인·창 모드·플랫폼별 입력은 해당 실행물에서 검증하고 미확인 항목을 남깁니다. 근거: GR-456.
- DD-023: 실제 접근 가능한 개발 환경, AI 편집/실행/관찰 도구, 무료 그래픽 가공, 픽셀/쿼터뷰, Windows 배포와 요구 성능의 근거를 검토해 엔진을 선정합니다. 두 엔진으로 같은 게임을 먼저 만들도록 작업을 늘리지 않습니다. 근거: GR-457·360·451~454.
- DD-024: 핵심 상태와 시간 처리를 화면 표현에서 분리해 재고·이전/소비·결제/환불·수출 출발·기한/파괴 우선순위를 반복 확인하는 자동 검증을 먼저 마련합니다. 직접 플레이 체감 검증을 대체하지 않습니다. 근거: GR-458·443.
- DD-025: 첫 전체 흐름 연결 후 대표 후반 물량·4배속 부하를 추가하고 기능 확장에 따른 변화를 기록합니다. 성능 최적화가 수량·시간·승패를 바꾸지 않는지도 확인합니다. 근거: GR-459.
- 상세 계획은 [technical-validation.md](technical-validation.md)를 따릅니다. 아직 선정·구현·자동 테스트·성능 측정은 수행하지 않았습니다.

## 테스트·배포·검토 주기에서 도출한 설계

- DD-026: 작은 버전의 사용자 본인 검증·내부 자동 검증은 반복하되, 본인 외 테스트 준비는 MVP 기능·기본 표현 완성 뒤로 둡니다. 이 계획만으로 사람에게 초대·링크·파일을 보내지 않습니다. 근거: GR-460.
- DD-027: MVP 평가의 우선 근거는 기존 승리 조건으로 한 판을 완수하는 경험입니다. 모든 웨이브 전멸·무피해·기록 경쟁을 새 필수 목표로 추가하지 않습니다. 근거: GR-461·223·448.
- DD-028: 사용자는 평소처럼 플레이하고 체감을 전달합니다. AI는 확보한 실행/이벤트 지표와 피드백을 실행 조건·현상·해석·다음 조정안으로 정리합니다. 새 리플레이·중도 저장·외부 전송 기능을 만들지 않습니다. 근거: GR-462·443·458.
- DD-029: 첫 제품 패키지는 독립 Windows 실행과 오프라인 사용을 기준으로 검증합니다. 상점 계정/플랫폼 API 연동·게시 작업을 MVP의 선행 작업으로 두지 않습니다. 근거: GR-463.
- DD-030: 후속 검토는 작은 실행 버전, 구체 변경, 실제 수행한 검증과 남은 미확인 사항을 한 묶음으로 제공합니다. 개발 세부마다 선호 질문을 늘리지 않고 중대한 원칙 충돌만 다시 묻습니다. 근거: GR-464.
