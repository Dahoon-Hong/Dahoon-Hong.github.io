# Project C 첫 검증 버전 계획 — Q-494 반영

- 근거: [확정 기획](planning.md)의 GR-440~444와 [공통 설계 원칙](design-principles.md).
- 목적: 임시 그래픽·기본 UI로 수입→생산→보급→방어→수출이 연결되는지 직접 플레이와 지표로 함께 확인합니다.
- 이 문서는 원칙에서 도출한 검증 계획입니다. Q-480~482에서 Unity+C#·3D 모델/픽셀 느낌·Windows x64를 확정했습니다. 구현·플레이·성능 검증은 아직 실행하지 않았습니다.

## 첫 검증의 범위

| 연결 구간 | 확인할 실제 사건 | 최소한의 화면 정보 |
| --- | --- | --- |
| 수입 | 주문 확정/선결제, 실제 접안, 철 순차 하역 | 자금·계약/선박 상태·항구 실재고 |
| 생산 | 실제 원료 반입, 철판과 탄약 생산 완료 | 시설 종류·품목·입출력·가동/대기 원인 |
| 보급 | 생산측 탄약의 전초기지 입고와 전투측 반출, 터렛 실제 납품 | 전초기지 목표/적용값·실재고·예약/운반 중·터렛 탄약 |
| 방어 | 정해진 진입점에서 등장, 이동/차폐, 유효 사격·탄약 소비·피해 | 적/시설 식별·필요 체력바·선택 사거리·웨이브 정보 |
| 수출 | 실제 채취/정제, 항구 수출 재고, 선적과 실제 출발 정산 | 원석/결정 실재고·수출 계약·선박 상태·인정 수출량 |

- 첫 검증 목표는 모든 최종 자산을 완성하거나 특정 승률을 입증하는 것이 아니라 한 흐름에서 실제 상태가 이어지는지 확인하는 것입니다.
- 기존 초기 시설·재고0·첫 철100·드론5대·전초기지 필수 중계·선박 시간표를 사용합니다. 안내를 위해 무료 물자를 더하거나 처음부터 벨트를 연결하지 않습니다.
- 첫 보급/교전과 첫 결정 수출의 연결을 확인한 뒤 후반 부하·기한 내 목표 달성 검증을 넓혀갑니다. 최종30웨이브·결정2000개·3900초 미만 출발 요구는 유지합니다.
- 별도 단축 모드·여러 지도·독립된 추가 게임을 MVP 기능으로 만들지 않습니다.

## 직접 플레이와 지표의 결합

| 플레이에서 확인할 것 | 함께 기록할 근거 | 판단에 사용하는 방식 |
| --- | --- | --- |
| 무엇을 해야 하는지 이해되는지 | 첫 하역·철판·탄약·터렛 보급·첫 수출 시각 | 어디서 설명/조작/수송 때문에 막혔는지 구분 |
| 작은 실수를 발견하고 복구할 수 있는지 | 문제 발생·발견·수동 조치·실제 정상화 시각, 자재/피해 변화 | 모든 실수를 구제하지 않으면서 기본적인 조치 후 회복 여유가 있는지 평가 |
| 중반 증설이 의미 있는지 | 방어 보급 중단·시설 대기·수출 유출·자금 변화 | 확장의 효과와 다른 공급망의 희생이 드러나는지 평가 |
| 후반에 공급망 유지가 시험되는지 | 적 수·탄약 수요·물류 지연·전초기지 피해 | GR-438의 압박 곡선과 실제 플레이를 비교 |
| 기록과 실제 게임이 일치하는지 | 자원 이전·소비·회수·결제/환불·출발 정산 | 누락·중복·음수 재고·이중 결제 등을 기능 오류로 구분 |

- 기록은 검증용 자료입니다. 기존 결과 통계5개 외의 새 고급 통계 UI를 추가하지 않습니다.
- 단일 체감이나 단일 숫자만으로 밸런스를 확정하지 않고 해당 실행의 상황·지표·해석을 함께 남깁니다.
- 작은 실수의 회복 시간·허용 피해량 등 정량 기준은 아직 실행 자료가 없으므로 임의로 합격 숫자를 만들지 않습니다.

## 문제별 조정 순서

1. 입력·재고·시간·경로·결제 등 기능이 확정 규칙대로 동작하는지 먼저 확인합니다. 기능 오류는 기능 수정으로 해결합니다.
2. 규칙은 정상인데 목표한 경험이 나오지 않으면 병목과 실행 자료를 확인합니다. 속도·비용·초기 배치 등 현재 규칙 안의 조정안부터 검토합니다.
3. 현재 규칙 안의 조정으로 핵심 경험이 해결되지 않을 때 기본 규칙 변경의 이유·영향을 정리합니다. 확정 GR을 조용히 덮어쓰지 않습니다.
4. 확인한 변경만 기록과 플레이로 재검증합니다. 구현하지 않은 성능·후반 승리 가능성을 달성했다고 표시하지 않습니다.

## 임시 그래픽·기본 UI의 기준

- 단순 도형이나 임시 스프라이트를 사용해도 시설·적·드론·품목·구역을 식별할 수 있어야 합니다.
- 선택·배치 불가·문제 원인은 색만으로 설명하지 않습니다. 벨트 방향은 기존 애니메이션 표현을 따르며 방향 화살표·글자를 추가하지 않습니다.
- 기본 UI는 실제 상태와 유효 조작을 연결합니다. 정식 픽셀 아트 수준과 장식·정교한 연출은 이후 적용합니다.
- 기존 한국어/영어·UI 배율·최소 화면·성능 목표는 최종 요구로 유지하고 실제 검증 여부를 따로 기록합니다.
- 검증 순서가 정해졌다는 이유로 엔진을 선택하거나 에셋을 구매·설치하지 않습니다.

## 플레이 판단·운영 부담의 평가 — GR-445~449에서 도출

| 기준 | 함께 확인할 플레이·기록 | 유지할 제약 |
| --- | --- | --- |
| 현재·다음 국면 중심 정보 | 현재 문제와 가까운 다음 준비에 필요한 정보가 부족/과잉인지 | 전체 지도 공개·기한/시간·비용/결과 안내 유지 |
| 드론 보조·벨트 대량 수송 | 반복 대량 운반의 벨트 효과, 변동/현장 수요의 드론 유연함 | 현재 속도·적재·대수·처리량 유지 |
| 계획형 정지 활용 | 어디서 멈춰 설계·점검하는지와 재개 후 문제 해결 여부 | 메뉴가 자동 정지/재개하지 않는 규칙 유지 |
| 피해 감수 전략 | 방어 증설·수리·수출 확장의 지출/피해/진행 차이 | 무피해 강제·자동 수리·패배 조건 변경 없음 |
| 후반 용량·공간 병목 | 수출 안정 이후 자금 잔액·처리/수송 대기·배치 여유 | 결제 제약을 무시하거나 현재 가격/지원금 변경 안 함 |

- 평가 결과는 아직 없습니다. 목표 경험이 나오는지는 실제 구현 후 직접 플레이와 지표를 함께 확인합니다.

## 실행·검증 경로 — GR-455~459 반영

- 초기 브라우저 미리보기도 허용하되 최종 Windows 호환성·오프라인·창/입력 동작은 실제 Windows 실행물에서 따로 검증합니다.
- 엔진은 환경·무료 자산·AI 연동 요건 검토 후 하나를 선택합니다. 두 후보로 각각 같은 전체 흐름을 만드는 비교를 필수 작업으로 두지 않습니다.
- 재고·거래·승패 자동 검증을 먼저 마련하고, 작은 전체 흐름 직후부터 후반 물량/4배속 성능 검증을 병행합니다.
- 상세 근거와 미확인 항목은 [technical-validation.md](technical-validation.md)에서 관리합니다. 현재 실행·측정 결과는 없습니다.

## 테스트 참여·완료 경험·검토 주기 — GR-460~464 반영

- 개발 중 사용자는 자유롭게 플레이하고 체감 피드백을 줍니다. AI는 해당 실행의 확보한 기록과 지표를 정리하며 사용자에게 세부 체크리스트 수행을 기본으로 요구하지 않습니다.
- 한 판 완수의 성취를 우선 평가하되 첫 작은 전체 흐름 검증과 최종 승리 조건 검증을 구분합니다. 모든 웨이브 전멸·무피해를 새 필수 조건으로 만들지 않습니다.
- 본인 외 테스트는 최종 MVP 기능과 기본 표현이 갖춰진 뒤 준비합니다. 현재 사람을 초대하거나 파일/링크를 공유하지 않습니다.
- 작은 실행 버전마다 변경·실제 검증·미확인 사항을 묶어 확인합니다.

## 첫 검증판의3D 표현 — GR-485~489

- 임시3D 모델·기본 UI로 작은 전체 흐름을 연결하되 대표 시설·지형에는 픽셀 느낌·직교 카메라·일정한 조명·절제된 그림자의 방향을 함께 적용합니다.
- UI·글자는 선명하게 유지하고 모델의 형태·높이로 가림을 줄이며 선택 윤곽을 확인합니다. 전체 정식 자산 완성을 첫 버전의 선행 조건으로 삼지 않습니다.
- 직접 플레이와 대표 화면·상태 기록으로 기능 식별·물류 관찰·배치 판단을 검토합니다. 기존 시안의 묘사 기준을 실제3D 장면이 만족하는지 별도로 평가합니다.
- 아직 실제 모델·셰이더·실행판·성능 측정 결과는 없습니다.

## 완주 해법 평가 — GR-493

- 첫 작은 전체 흐름을 연결한 뒤 정식 한 판 검증에서 서로 다른 합리적인 배치·증설 순서의 완주 가능성을 평가합니다. 몇 가지 내부 사례의 성공을 모든 배치의 성공 보장으로 확대하지 않습니다.
- 사용자의 자유 플레이 피드백과 진단 기록을 AI가 정리하는 기존 방식을 유지합니다. 플레이어에게 검증 체크리스트 수행을 기본 부담으로 요구하지 않습니다.
