# Project C — Codex 시작 지침

## 먼저 읽기

1. development-handoff.md의 현재 상태·확정 방향·개발 순서를 읽습니다.
2. planning.md의 상단부터 Q-494 확정과 질문 방식 교정까지 읽습니다. 최신 GR이 과거 기록에 우선합니다.
3. software-architecture.md, first-validation.md, technical-validation.md를 읽고 큰 구조·검증 경계를 따릅니다.
4. 작업 대상에 맞춰 asset-plan.md, ui-flow.md, event-rules.md, drone-rules.md, play-flow.md 및 reference의 원문을 조회합니다. 과거 기록의 미정·상태 문구를 최신 결정으로 오인하지 않습니다.

## 확정 방향

- Unity+C#, 실제 Windows 개발 머신, Windows10/11 x64 오프라인 독립 실행물.
- 화면 없이 검증 가능한 C# 규칙 코어와 Unity 입력/표현/플랫폼 계층을 분리합니다. 수치는 데이터·작동 규칙은 코드로 관리합니다.
- 고정 쿼터뷰 직교 카메라로3D 모델을 표시합니다. 게임 장면에 픽셀 느낌, UI·글자는 선명하게 유지합니다. 실제 점유/충돌/사거리/시간은 코어 규칙을 따릅니다.
- 무료 자산+보정, AI 열람·수정·검증 가능, 에셋 구매 총5만원 이하/음향 우선. 원본·가공 방법·최종본·실제 사용 조건을 함께 관리합니다.
- 공개 Git 저장소 방침이며 실제 보관·배포가 허용되는 자산만 포함합니다. 실제 저장소는 아직 만들지 않았습니다.
- 첫 목표는 수입→생산→보급→방어→수출의 작은 전체 흐름과 대표 장면입니다. 전체 정식 아트를 선행하지 않습니다.
- 재고·거래·승패 자동 검증을 먼저 마련하고 정확성 결함은 기능 확장보다 먼저 수정·재검증합니다. 로컬 진단을 자동 기록하고 첫 Windows 버전은 ZIP으로 제공합니다.

## 진행과 질문

- 이 문서 묶음에는 기획·큰 구조·검증 계획이 있습니다. 현재 실제 게임 코드·Unity 프로젝트·컴파일/테스트/성능 결과는 없습니다. 개발 머신에서 실제 상태를 확인합니다.
- 기존 원칙에서 도출 가능한 모듈 내부 구조·도구·파일 구성·일반 최적화는 AI가 결정하고 근거를 남깁니다. 질문 수·묶음 수를 채우기 위한 설문을 만들지 않습니다.
- 목표·범위·예산·핵심 경험을 바꾸는 선택이나 중대한 충돌, 실제 중요한 엔진 제약, 무료 자산과 보정으로 표현을 충족하기 어려운 경우에만 원인·영향·대안을 갖춰 질문합니다.
- 새 판단이 필요하지 않으면 설계를 구체화하고 구현·검증을 진행합니다. 실제 기존 프로젝트가 있으면 먼저 분석하고 작업을 보존합니다.
- 규칙·설계 변경과 수행한 검증·미확인 사항을 Markdown과 Git에 남깁니다. 사용자에게는 작은 플레이 버전과 해당 변경·검증 결과를 제시합니다.
