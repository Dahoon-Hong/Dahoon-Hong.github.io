# Project C 실행 환경·품질 검증 계획 — Q-494 반영

- 근거: [확정 기획](planning.md)의 GR-455~459와 [첫 검증 계획](first-validation.md).
- 개발·초기 검증 환경은 자유롭게 선택하고 초기 브라우저 미리보기도 허용합니다. 최종 목표는 기존 Windows10/11·PC 오프라인 실행입니다.
- 엔진은 Q-480에서 Unity+C#으로 선택했습니다. Q-481의 표현 방식은 고정 카메라의3D 모델에 픽셀 느낌을 적용하며 첫 실행 대상은 Windows x64입니다. 실제 설치·구현·실측 결과는 아직 없습니다.

## 실제 개발 환경·인계 — GR-465~469

- 실제 개발은 다른 Windows 머신의 Codex 세션에서 진행합니다. 현재 임시 실행 환경의 설치 상태로 엔진 적합성을 판단하지 않습니다.
- 초기 도구 설치·연결부터 가능한 한 AI가 처리하는 방식을 우선합니다. 실제 연결 가능 여부와 사람의 개입이 필요한 절차는 개발 환경에서 확인합니다.
- 코드·Markdown 기획·설계·검증 기록은 Git 저장소에 함께 관리하는 방향입니다. 실제 저장소는 아직 정하지 않았습니다.
- 큰 소프트웨어 구조와 주요 기술 선택은 개발 세션에 넘기기 전에 설계합니다. Q-470~474의 구조 설계 원칙은 확정됐으며 software-architecture.md에 엔진 공통 구조 초안을 정리했습니다.
- 엔진 선택 단계에서 정확한 버전 확인·설치를 필수 선행 작업으로 두지 않습니다. 선택을 좌우하는 호환 요건은 확인하고 구체 버전 고정은 선정·환경 구성 시 수행합니다.
- 중요한 엔진 제약이 발견되면 원인·영향·대안을 정리해 사용자에게 질문합니다. 엔진 교체나 요구 변경을 임의로 확정하지 않습니다.

- 두 엔진 각각의 전체 흐름 시제품을 필수로 만들지 않습니다. 선정 후 한 경로에서 작은 전체 흐름을 구현하며, 중대한 미충족 요건은 이유와 대안을 드러냅니다.

## 핵심 자동 검증의 우선 범위

- 물자 보존: 창고/시설·벨트·드론·현장·회수 더미 사이 이전과 생산/건설/수리 소비에서 누락·중복·음수 재고가 없는지.
- 거래: 확정 시 선결제, 미입고 환불, 선적과 실제 출발 정산, 같은 주문/사건의 중복 반영 방지.
- 승패·시간: 동일 게임 시계·배속/정지,3900초 미만 출발, 동시 전초 파괴 우선, 치명 피해 우선, 취소/완공 우선순위.
- 현재 확정 규칙에서 기대값을 정합니다. 단순한 내부 함수 구조를 복사하는 검사보다 실제 규칙 경계와 물자/자금의 불변 조건을 확인합니다.
- 자동 검증 결과와 직접 플레이·핵심 지표를 함께 기록합니다. 아직 테스트 코드는 작성/실행하지 않았습니다.

## 조기 성능 검증

1. 작은 전체 흐름이 연결되면 대표 후반 적 수·드론 활동·벨트/시설 부하를 재현할 내부 검증 상황을 준비합니다. 새 게임 모드로 제공하지 않습니다.
2. 1080p와1/2/4배를 확인하고 실제 기기·OS·실행물·상황·측정 방법을 함께 기록합니다. 내장GPU·RAM8GB 대상의 구체 기기는 후속 확인합니다.
3. 기능 확장 후 같은 기준에서 변화를 확인하고, 최적화가 재고·시간·승패 결과를 바꾸지 않는지 핵심 자동 검증과 연결합니다.
4. 아직 확보하지 않은 CPU/GPU·메모리 예산·프레임 측정 결과를 임의로 채우거나 목표60FPS를 달성했다고 표시하지 않습니다.

## 독립 실행물 우선·검토 산출물 — GR-463·464 반영

- MVP 검증 대상은 독립 실행 Windows판입니다. 상점 플랫폼 API/계정/게시 연동은 후속 범위로 둡니다. PC 판매 목표와 오프라인 플레이 요구는 유지합니다.
- 버전별로 실행 조건·구체 변경·수행한 자동/직접 검증·측정 결과·미확인 사항을 함께 기록합니다. 문서 계획을 실제 실행 결과로 표시하지 않습니다.

## 구조 설계 원칙 연결 — GR-470~474

- 재고·거래·전투의 권위 있는 상태와 판정은 화면 없이 검증하는 코어에 둡니다. 화면·오디오·입력은 해당 코어의 결과를 표시하거나 명령으로 전달합니다.
- 수치 데이터는 작동 규칙 코드와 분리합니다. 설정 파일 오류나 모순은 개발 검증에서 발견하고 확정 값을 조용히 대체하지 않습니다.
- 개발용 재현 기록에는 버전·초기 조건·주요 명령·오류 상태를 남기는 방향이며 Q-477에 따라 로컬 파일에 자동 기록합니다.
- 확장 준비는 시설·품목·적 추가와 수치 변경까지입니다. 상세 구조 초안과 검증 경계는 [software-architecture.md](software-architecture.md)를 따릅니다.

## 개발 전환 원칙 연결 — GR-475~479

- 엔진 선택은 Q-480에서 Unity+C#으로 마쳤습니다. 비교 근거는 [engine-review.md](engine-review.md)에 보존하며 실제 개발 머신의 연결·실행 확인은 후속입니다.
- 단축 시험과 정식 한 판 시험의 초기 조건·설정·결과를 구분합니다. 승패·경제·성능 완료 판단은 해당 확정 요구를 실제로 검증한 결과를 근거로 합니다.
- 버전·초기 조건·주요 명령·오류 상태·측정 기록을 판 식별자에 연결해 로컬 파일에 자동 기록하는 설계입니다. 기록 형식·용량 관리는 구현 단계에서 도출합니다.
- 재고·거래·승패 결함은 수정 후 관련 재현과 핵심 규칙 검증을 다시 통과한 뒤 기능 확장을 이어갑니다.
- 첫 Windows판은 실행 파일과 필수 데이터를 포함한 ZIP입니다. 개발 머신에만 설치된 도구나 외부 네트워크 의존 없이 실행 가능한지 실제 Windows에서 검증합니다.

## 엔진·3D·지원 범위 연결 — GR-480~484

- 선택 결과와 실제 동작 증거를 구분합니다. Unity+C#은 확정했지만 Editor 연결·패키지 적합성·라이선스 적용·Windows 실행·성능을 검증했다고 표시하지 않습니다.
- C# 코어의 격자·거리·시계·재고·거래·승패를3D 표시와 분리해 자동 검증합니다. 보이는 모델이나 시각 연출이 판정을 바꾸지 않게 확인합니다.
- 3D 모델·재질·픽셀 표현 효과의 실제 비용을 후반/4배속 부하와 함께 측정합니다. UI 배율과 지도 픽셀 표현을 별도로 확인합니다.
- 검증 대상은 Windows10/11 x64입니다. Windows on ARM을 별도 지원 목표에 포함하지 않습니다.
- 기반 패키지는 무료 후보의 용도·사용 조건·AI 작업 가능성·선택 Unity 환경 호환성을 확인합니다. 실제 설치는 다른 개발 머신에서 수행합니다.
- 무료3D 자산과 보정으로 승인한 표현을 충족하기 어려우면 후보·부족한 점·대안을 정리해 사용자에게 질문합니다. 신규 제작·구매·예산 재배분으로 임의 전환하지 않습니다.

## 3D 표현 검증 연결 — GR-485~489

- 픽셀 느낌을 적용한 게임 장면과 선명한 UI·글자의 합성을 실제 해상도·한/영·UI 배율에서 확인합니다. 구체 내부 해상도·효과 방식·렌더 파이프라인은 아직 선택하지 않았습니다.
- 고정 쿼터뷰 직교 카메라의 이동/줌에서 격자 선택·배치·모델 크기·기능 식별이 일치하는지 확인합니다.
- 일정한 조명·절제된 그림자에서 시설 종류·물자·적을 구분하고, 가림이 적은 모델 형태·높이와 선택 윤곽이 실제 코어 대상에 대응하는지 확인합니다.
- 첫 작은 전체 흐름 검증판에 대표 시설·지형의 새 표현을 포함합니다. 완성 아트 전체를 선행하지 않으며 실제 화면·부하를 확인하기 전 달성으로 표시하지 않습니다.

## 검증·진행 책임 연결 — GR-490·493 및 질문 방식 교정

- 시각 비용과 목표가 충돌하면 측정 근거를 바탕으로 그림자·후처리·장식 효과부터 조정합니다. 기능 식별·규칙·정확성을 유지하고 실제 성능을 재확인합니다.
- 밸런스 검증은 여러 합리적인 배치·증설 순서의 완주 가능성을 평가합니다. 현재 수치를 임의 수정하지 않고 결과가 요구에 못 미치면 근거와 조정안을 기록합니다.
- 내부 자료구조·진단 파일 구성·일반 최적화·검증 도구 선택은 확정 원칙에서 AI가 도출합니다. 사용자가 결정해야 하는 목표·범위·예산·핵심 경험의 변경이나 실제 제약 충돌만 질문합니다.
